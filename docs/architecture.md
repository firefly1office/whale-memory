# 架构：自传层与完整引擎

这份文档讲清楚两件事：**仓库里有什么**，以及**它当初是按什么设计思路长出来的**。完整引擎不随本仓库分发。

## 分层

```
┌─────────────────────────────────────────────┐
│ 宿主（QQ Agent / DSH / 自建 agent）           │
│  工具注册、提示词拼接、调度、会话标识           │
└───────────────┬─────────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────────┐
│ 自传层（本仓库 packages/core + adapters/cli） │
│  经历 then/later、召回、想起计数、醒来、        │
│  提示词 overlay、她自己的设置                   │
└───────────────┬─────────────────────────────┘
                │ 落盘
┌───────────────▼─────────────────────────────┐
│ JSONL 文件（<WHALE_DATA_DIR>/plugin-data/...） │
└─────────────────────────────────────────────┘
```

**不在本仓库的完整引擎**（在作者本机的 QQ Agent 部署里）：vault 存储与索引、evidence-policy 取证、consolidator 合并、注入预算、跨会话可见性、宿主工具注册。这部分约 26k 行，与具体宿主的路径、会话键、部署习惯强耦合，不适合直接公开分发。

## 三条核心设计

### 1. 经历是事件，不是状态

`then` 在写下时固定，`later` 只追加。这不是"版本控制"，是把**事件溯源**用在人格连续性上：

- 她今天改了看法，不会让昨天那句消失
- 读取时才知道"当时 / 现在"，而不是存的时候就合并掉
- 旧看法被新看法覆盖，等于篡改历史——这是这个项目最重要的红线

### 2. 证据优先（完整引擎里的 evidence-policy）

本仓库的 `then.quote` / `then.state` 是给取证留的锚。完整引擎在回答历史事实时会做三件事：

- **as-of**：只返回某个时间点之前成立的记录
- **被取代**：旧值不冒充新值；新值要能说明它取代了谁
- **后继缺席**：没有后继记录时，如实说"没有后续"，不推断

没有证据就说"没有记录"。这不是话术，是检索层的判定。

### 3. 写入与读取分开

- 写入：追加一行，补真实换行；有坏行时拒绝改写、保留原行
- 读取：跳过坏行；`recall(mark:false)` 只读不写
- 想记"想起了一次"：显式 `mark:true` 或调用 `markRecalled`

`later` 和「想起」都是追加事件（`later-events.jsonl` / `recall-events.jsonl`），经历正文只追加；追加走锁，多进程写同一目录不会丢行。`then` 仍然不可变。

## 召回怎么工作

```
候选池 = 经历（可选 + 日记）
分词   = 中文 bigram（无词典、零依赖）
去噪   = 虚词表（今天/什么/我的/是不是…）不进 bigram
过线   = 原始重叠数 ≥ minOverlap；长查询（≥8 字）要求命中 ≥60% 的 bigram
分数   = 原始重叠数 × 重要度权重（权重不影响门槛）
排序   = 分数降序，同分按时间
```

长查询按比例要求，是为了让「量子力学与广义相对论」这类长而具体的问句在真实语料里也能诚实地返回空，而不是靠命中一个「相对」就凑出来。短查询（如「灯塔」）不受比例约束。

它不追求"召回准确率"，因为本项目的取向下召回正确率不是目标。`tools/eval-recall.mjs` 只验证两件事：**该中的能中**、**不该编的确实为空**；`tests/recall-quality.test.mjs` 用 200 条合成语料守住后者。

## 为什么没有做向量检索

- 这个项目的数据量级是几千条，bigram 够用
- 向量检索会引入模型依赖和不可解释的相似度，与"证据优先"冲突
- 真正缺的不是语义相似度，而是**原文锚与后续记录**——先把这个做好

## 如果要接自己的宿主

1. 读 [`porting.md`](porting.md) 的宿主最小契约
2. 用 `packages/core` 打底，按需实现注入与调度
3. 隐私边界自己做：日记只在一对一、别人的私事不跨会话
4. 单写者约束自己保证
