# 夜间整理最简版（nightly-consolidate）

> 借自 ru-гу 的「夜里对着原话回看一遍」与 Lysmor 的衰减思路（AGPL，只学设计，未复制代码）。
> 代码：`tools/nightly-consolidate.mjs`；测试：`tests/nightly-consolidate.test.mjs`（24 条）。
> **只落事件，不接读路径**：这一版像 S1 的事实键一样只有数据层——建议写进
> `consolidate-events.jsonl`，没有任何模块读它，也不会自动生效。

## 它做什么

晚上跑一次，对着**原话**回看白天的记录，给三种建议：

| 建议 | 什么时候提 |
| --- | --- |
| `quote-not-in-source` | 后记里引了「……」的一段，但这条经历的原话（`then.text` / `then.quote.text`）里找不到 |
| `quote-not-in-quote` | 她自己写的话里引了「……」，但读到的原文（`then.quote.text`）里没有 |
| `merge-later` | 同一条经历写了 2 条以上后记，建议按时间顺序归并成一条 |
| `merge-topic` | 两条以上经历讲同一件事（`then.refs` 相连，或关键词重叠够多），建议归并成一条 |

结果是**建议**，不是结论：不改记录、不删后记、不合并正文。要不要照办，由人看完 diff 决定。

## 它不做什么（明确写清）

- **不接读路径 / 召回**：没有模块 import 这个工具，`consolidate-events.jsonl` 也没有任何读者。
- **不原地改记录**：`self-experience.jsonl` 与六类既有事件文件一个字节都不动（测试里逐文件 sha256 比对）。
- **不碰封存与抽屉**：封存的经历整条跳过（连正文和 id 都不带进建议），`unsaid.jsonl` 根本不读。
- **不调模型、不联网、零第三方依赖**：判据是确定性的字符串比对与词重叠，没有"让模型看看哪里不对"。
- **不调度**：没有 cron / 宿主钩子；要跑得人手动跑（这是"默认关"的一部分）。

## 判据

### 1. 对照原话（两道引文核对）

只认**成对引号**里的内容：「」『』“” 与直双引号 `"…"`。原因：没有引号的话是叙述，不是"她引了原话"，
拿整句去比原话，等于要求她的每一句转述都逐字一致，误报会淹掉真问题。

比对口径与 `query-match.js` 一致：先小写、去掉空白与标点（`normalizeText`），再比子串。

- 引文片段太短（去掉标点后不足 2 字）不核对：「嗯」「好」这种几乎到处都能碰巧命中。
- 引文超过 120 字不核对：那是整段复述，不是一句引文。
- `then.text` 和 `then.quote.text` 合起来算"这条经历的原话"；两道检查分别用「合起来」和「只有
  `then.quote.text`」，因为第二道问的就是"她写的话有没有歪曲她读到的原文"。

不做的事：不核对事实真假、不判断数字对不对、不判断"他到底说没说"。那是内容层，这一版只管引文。

### 2. 同一条经历的多条后记

`later-events.jsonl` 里同一 id 有 2 条以上后记 → 一条 `merge-later`。建议里按时间列出每条的
日子与前 24 字，归并后的写法也一并给出（按时间用「；」连接），但不替她动笔。

### 3. 同主题的两条以上经历

两条判据，任一成立：

1. **显式引用**：一方的 `then.refs` 里有另一方的 id（她/宿主自己连过线，最强证据）。
2. **关键词重叠**：用 `query-match` 的两字组 / 整词口径（停用词、垫话已经滤掉），要求
   - 交集 ≥ 3 个词；
   - 交集占较短一方 ≥ 60%（避免一条很长的记录拿两三个常见词把短记录拉进来）。

再加三道闸，防止"整库归并"：

- **背景词过滤**：全库 ≥ 50% 的经历都出现的词不算主题词（「今天」「什么」这种已经在停用词表里；
  这条是按数据算的兜底，模板化的记录就是靠它不互相归并）。少于 5 条经历时不启用。
- **一组最多 8 条**：再大就不是"同主题"，是"整库"。
- **超过 2000 条经历就跳过主题归并**：两两比较是 O(n²)，这一版没做索引；跳过了会在输出里明说。

分组是贪心：每条只跟"组里第一条"比，不顺着链子把整库连成一团，结果确定、可解释。

## 事件格式

`consolidate-events.jsonl`，一行一个 JSON，只追加：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `v` | 是 | 固定 `1`（事件格式版本） |
| `type` | 是 | `quote-not-in-source` / `quote-not-in-quote` / `merge-later` / `merge-topic` / `undo` |
| `id` | 是 | 建议 id：`cons_` + 12 位 sha1 前 12 位。同一份数据重复算得到同一个 id |
| `ids` | 是 | 这条建议涉及的**经历 id** 列表 |
| `at` | 是 | 写入时刻（ISO 8601） |
| `day` | 是 | 写入那天（本地日，`sv-SE`） |
| `summary` | 是 | 建议内容（人读；封顶 500 字） |
| `reason` | 是 | 为什么提这条（判据 + 来源；封顶 300 字） |

- **id 稳定**是幂等的基础：内容没变，`--write` 只写一次；内容变了（例如又加了一条后记），
  会得到一个新 id、写一条新建议，旧建议仍留在文件里（append-only，不自动失效）。
- **撤销**是另一种事件：`{v:1, type:'undo', id:'<被撤销的建议 id>', ids:['<同一个 id>'], ...}`。
  不删、不改原建议，只是追加一条"这条不算数了"。
- 建议 id 一旦在文件里出现过（哪怕后来被撤销），`--write` 就不再写它——撤销过 = 处理过。

写盘时用 `file-lock` 的同一把锁（`consolidate-events.jsonl.lock`），追加前检查文件末尾有没有换行，
不重写文件。事件先构造后校验，写不出合格的一行就不写。

## dry-run / --write / --undo

```bash
node tools/nightly-consolidate.mjs <memory-dir>            # 默认 dry-run：只打印建议 diff
node tools/nightly-consolidate.mjs <memory-dir> --write    # 追加建议事件
node tools/nightly-consolidate.mjs <memory-dir> --undo     # 撤销最后一条建议
node tools/nightly-consolidate.mjs <memory-dir> --undo --id cons_xxx
node tools/nightly-consolidate.mjs <memory-dir> --json     # 机器可读
```

dry-run 打出来的是能看的 diff（`-` 是看到的事实，`+` 是建议，理由单列）：

```
夜间整理（dry-run：只看不写）：/tmp/whale

读到的：经历 2 条（跳过封存 0 条）；后记 2 条；引文核对 2 处

建议 3 条：

[1] quote-not-in-source  cons_ad4175eb7e10  ids=exp_a
    - 后记里的「船已经靠岸」在原话里找不到；这条的原话是：读完灯塔故事的上半篇，靠在窗边 潮汐终会归来
    + 建议：重写这条后记，按原话改；原话里没有的就别引
    理由：后记（2026-11-17）引了这段，但 then.text / then.quote.text 里没有

[2] merge-later  cons_9459634c6578  ids=exp_a
    - 2026-11-15「他说过「潮汐终会归来」，我记下了」
    - 2026-11-17「他又说「船已经靠岸」，可原文不是这样」
    + 建议：把这一条的 2 条后记归并成一条：…
    理由：同一经历有 2 条后记（2026-11-15、2026-11-17），建议按时间顺序归并成一条

[3] merge-topic  cons_f3f3ce9abb6d  ids=exp_a,exp_b
    - 2026-11-14「读完灯塔故事的上半篇，靠在窗边」
    - 2026-11-16「灯塔下的纸船，被潮汐带走了」
    + 建议：把这 2 条同主题的经历归并成一条：…
    理由：2 条经历由 then.refs 显式相连

dry-run 结束：没有写任何文件。要落盘加 --write（只追加 consolidate-events.jsonl）。
```

- **默认 dry-run 一个字节都不写**：不建文件、不建锁、不建目录（测试对整个目录做 sha256 指纹前后比对）。
- `--write` 只追加新建议。**幂等**：同一份数据再跑不会重复写；撤销过的不再写。
- `--undo` 本身是写操作（它要追加撤销事件），不需要再给 `--write`；重复 `--undo` 是 noop、不报错。
  `--undo` 只读整理事件文件，**经历文件坏了也撤得掉**。
- 输出语言固定中文；`--json` 给机器读（`counts` / `suggestions` / `written`）。

退出码：`0` 正常；`1` 数据目录读不出来 / 有坏行；`2` 用法错。

## 安全边界（都能在测试里看到）

1. **只写一个文件**：`consolidate-events.jsonl`。`--write` 前后对 `self-experience.jsonl` 与
   `later-events.jsonl` / `seal-events.jsonl` / `recall-events.jsonl` / `unfinished-events.jsonl` /
   `link-events.jsonl` / `chapter-events.jsonl` 逐文件 sha256 比对，必须完全一致。
2. **坏行 fail closed**：经历文件坏行（`EXPERIENCE_CORRUPT`）、后记文件坏行、
   整理事件文件自己坏行，一律退出 1，并且**不写任何东西**；坏文件原样留着，不被覆盖。
3. **封存不外露**：封存的经历整条跳过；测试里搜事件文件原文，确认封存正文、后记、连 id 都没出现。
4. **没有建议就不建文件**：空目录、只有一条经历、没有发现可整理的地方 → `--write` 不创建空文件。
5. **目录不存在不会被建出来**：直接退出 1（不静默当空库）。空目录（存在但没数据）退出 0。
6. **不重写、不删除**：`--undo` 之前写下的字节原样留在文件前缀里（测试用 `Buffer` 前缀比对）。

## 默认关怎么证明

1. **没有读者**。在 `packages` / `adapters` / `examples` / `plugin` 里搜 `nightly-consolidate` 与
   `consolidate-events`，**零命中**——没有任何模块引用这个工具或它的输出文件。
   包入口 `packages/core/index.js` 与 `packages/core/package.json` 一个字没动（搜 `nightly` 为空）。
   全仓搜 `nightly-consolidate` 只命中三处：工具本身、`tests/nightly-consolidate.test.mjs`、
   本文档（只是提到工具名）。
2. **没有自动运行**：没有 cron、没有宿主钩子、没有 npm script；`node tools/nightly-consolidate.mjs`
   不跑，就什么都不会发生。
3. **事件不生效**：`consolidate-events.jsonl` 不在 `erase` 的 `EVENT_FILES`、不在体检、不在任何
   读路径里；它就是一份给人看的建议记录。
4. **默认不写盘**：不传 `--write` / `--undo` 时，测试对整个目录做前后 sha256 指纹比对，完全相同。
5. **既有行为不变**：本段只新增 3 个文件（工具、测试、本文档），没有改任何既有文件；
   全量测试 769 → 793 条，原有用例全绿。

## 已知限制与没验什么

- **没有接进任何宿主**：真实跑法是手动执行；没有验证"每晚自动跑"的调度、失败告警、重复跑的开销。
- **没在真实数据上跑过**：测试都是临时目录里造的小样本（空 / 1 条 / 200 条）。
  真库里的旧格式记录、旧 id、几万条规模都没验；超过 2000 条时主题归并会跳过，这一点只验证了会跳过，
  没验证别的行为。
- **关键词判据是启发式**：两字组重叠 3 个 + 60% + 背景词过滤，是按经验和一次 200 条模板数据的误报
  （整库归并）调出来的，没有标注集，也没有算过准确率 / 召回率。同义词、换一种说法就认不出来。
- **引文核对只覆盖成对引号**：没有引号的转述、间接引语、数字错误都不抓。
- **事件没有自动失效**：内容变了会产生新 id 的新建议，旧建议仍留在文件里；要不要清理是别人的事。
- **没有 UI**：diff 只在命令行看；没有接管理页。
- **没做并发压力测试**：写盘走既有文件锁，但没验多进程同时 `--write` 的表现（只有单进程用例）。
- **没有做「摘要」这一层**：这一版没有"把一天写成一段摘要"的能力；`summary` 字段只是建议正文，
  不是对记忆的摘要。
