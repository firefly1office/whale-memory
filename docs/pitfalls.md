# 接之前先看：容易踩的坑

> [English](en/pitfalls.md) · 中文（本页）

这篇不是功能列表，是把“用起来会失望的地方”提前说清楚。每条都对应代码或论文里的证据。

## 1. 它不做语义检索

召回是字面匹配：中文按相邻两字组，英文按整词子串，没有向量、没有同义词词典。

- “下山”和“日落”不会互相命中。
- 问一件真事里没记下的细节（“围巾是什么颜色”），严格模式会返回空，连那件事本身也想不起来。
- 想覆盖同义说法，需要宿主在前面加一层检索，把 id 交给它；见 `docs/composition.md`。

## 2. 严格模式的阈值余量很薄

`MIN_COVER = 0.7` 是在 33 条虚构语料上选的。再高一点，正例会开始掉；再低一点，反例会回来。它不是“通用最优值”，换语料要重测。

## 3. 封存不是删除

封存后不再被主动想起，但原文、后记、备份包里的内容都还在。真正的删除只有整库 `purge`。

- 备份包是明文的，里面有封存和抽屉的原文。
- 不要承诺“删除某条记忆”；目前没有这个能力。
- 抽屉里“丢掉”也只是状态，原文仍在文件里。

## 4. 单写者，没有数据库

经历文件不加锁，依赖操作系统整行追加。事件文件有文件锁，但整体设计是单进程写入。

- 不要让两个宿主进程同时写同一个目录。
- 每次读取都全量重放，没有索引；几万条会明显变慢，十万条以上不合适。
- 并发写入的测试只覆盖本机 Windows/NTFS，不构成跨平台保证。

## 5. 核心层只分“一对一/不是一对一”

`waking.js` 和 `unsaid.js` 的会话门只判断是不是一对一会话，**不判断是谁的一对一**。

- “只有主人能看到”必须由宿主的主人门保证。
- 接入时如果宿主传错 `chatKey`，私聊内容可能进群聊。
- MCP 客户端被当作受信本机进程：连上就能读写全部记忆。

## 6. 提示词 overlay 是最弱的一环

overlay 会注入所有会话。第一个部署里，写 overlay 和回退 overlay 的工具没有主人门。

- 仓库版 `revert` 已改为只接受 `history.jsonl` 里出现过的快照名（2026-11-17，带回归测试）；第一个部署的插件版还没升级。
- 不要把 overlay 用在多用户场景；不要给不可信的人写权限。
- 改 overlay 前先备份 `prompt-overlay/`。

## 7. 评测很小，而且是自己出的题

- 语料 33 条、虚构角色“小舟”；开发集 60 条、留出集 32 条。
- 留出集也被看过结果后改过两条标签；论文里写了。
- 垫话包装的 333 条来自 37 条底子，不是独立样本。
- 不要把 92.9% / 73.1% 当成“通用准确率”；它只说明在这套语料上，严格模式比旧口径好。

## 8. 版本与发布状态

- 当前仓库与 npm 都是 **0.21.0**（tag `core-v0.21.0`）。论文对应的是 `v0.17.0`（提交 `549e51c`）；之后加的是模块（`changed` / `injection` / `fact-*` / `conversation-privacy` 等）与文档，严格模式的匹配口径没动（`MIN_COVER` 仍是 0.7）。
- 装之前还是先看 `npm view whale-memory-core dist-tags`——缓存和镜像偶尔会给旧版本。
- MCP 入口与英文文档以仓库为准。

## 9. 已知未修

- 宿主的 16 个工具没有主人门，包括写经历的工具；被诱导写入假记忆是现实风险。
- `recall` 核心库不校验 `limit`，传负数会返回“除最后一条以外的全部”。
- 提示词 overlay 的写入/回退工具在第一个部署里没有主人门。
- 线上第一个部署没有启用 cover 门；它的两条召回路径仍是旧口径。

## 10. 试过、不成立的：用字面门槛做跨窗口召回

我们把第 1 条那套字面匹配拿去试了另一件事：判断「当前这句话是不是在问别的房间聊过的事」。实测不成立，已停用。写在这里，省得下一个人重做。

做法：取当前这句当查询，去其他会话的历史里捞；命中 ≥1 个词、且其中 ≥1 个不是虚词，就算接得上。

15 轮真实样本（真实对话，不是造的场景）：判「接得上且有用」**0 条**；「沾边但没用」3 条；噪声 11 条；另有 1 条本来就没接上（不算错，也不算成绩）。

先把三类明显的 bug 修掉——她自己的名字不算内容、拍一拍这类系统提示不当问句、切词接缝拼出的假词（「你自己去」→「你自」「己去」）不算命中——触发从 14/15 降到 7/15。剩下 7 条全是字面撞车：

| 她听到的 | 捞出来的旧话 | 撞上的词 |
| --- | --- | --- |
| 「@小鲸鱼 出来」 | 「图我这边还是加载不出来」 | 出来 |
| 「一点是多少」 | 「所以是多少钱啊」 | 多少 |
| 「你自己去找」 | 「你可以去找大通要」 | 去找 |
| 「一个会话用久了会变笨吗」 | 「不知不觉这个会话已经 2 个亿了」 | 会话 |

原因是结构性的：**同一个原语，换了场景就不成立。** 这套口径在 `self-experience` / `self-memory` / `detail-recall` 里是对的——那是在「她自己经历过的事」里找工作，候选集是她自己的记忆，先验很强。搬到「别的房间别人说过的话」上，候选集大得多、先验弱得多，1 个内容词命中就从「勉强能召回」变成「噪声发生器」。加停用词只是追症状：换个样本就换一批撞车词。

结论边界，别扩大：这只说明**用字面匹配判断「是不是在问旧事」**不可行。它不说明跨窗口记忆不可行——要不要带、带多少，仍然是宿主的产品决定，见 `docs/cross-room-memory.md`。

这些不是“以后再说”的待办，是接入前就要知道的边界。要修，见论文第 8 节和 `docs/threat-model.md`。
