# 检索层评测（阶段 2）：200 条语料上的字面检索与混合检索

> 这一页回答一个问题：语料从 33 条扩到 200 条以后，现在的字面检索到底准不准；BM25 + 字符 n-gram + 小同义词表值不值得切默认。
>
> **结论：默认没切，仍然是字面检索。** 混合检索只在 `recall({ ranker: 'hybrid' })` 时生效。它在留出集上比字面检索高 **7.1 个百分点**（recall@10 70.7% → 77.8%，配对符号检验 **p = 0.039**），误召回率和封存/抽屉外露都还是 0。这个差距够小、样本也够小，先当"可选项"用，再观察。

## 一、怎么复跑

```sh
node tools/gen-eval-v2.mjs --check   # 磁盘上的产物与生成脚本一致
node tools/eval-v2.mjs               # 字面检索 vs 混合检索，开发集 + 留出集
node tools/eval-v2.mjs --tune        # 只打开发集（调参时用，不碰留出集）
node tools/eval-v2.mjs --check       # 安全边界（负例 / 封存 / 抽屉 / 标记外露）+ 指标回归线
node tools/eval-v2.mjs --json        # 机器读
# 语义排序（默认仍是桩；第三行见第八节）
node tools/eval-v2.mjs --ranker=embed                              # 桩
node tools/eval-v2.mjs --ranker=embed --embed-live                 # 现场 probe Ollama，接不上就照实打桩
node tools/eval-v2.mjs --ranker=embed --embed-cache=dev/embed-cache.jsonl   # 用预热好的真向量
```

不联网、不调模型（`--embed-live` 除外，它只连本机 Ollama）。语料写进临时目录，跑完就删。本机 Node 24.21 上两种排序加起来约 4 秒（每次会漂零点几秒）。指标下限在 `eval/thresholds-v2.json`，是回归线不是目标。

## 二、语料与用例

**语料 200 条经历**（`eval/corpus-v2.json`）：

- 前 33 条是 `eval/corpus.json` 里原来那个月的「小舟」，原样带过来（旧语料不删，回归还要用），14 个操作一起带；
- 后 167 条是新写的 2026-11-03 → 2027-02-04：校刊、话剧社、外婆家、期末、寒假，继续是同一个人；
- 全部是编的，不来自任何真实角色、真实聊天。生成是确定性的，同一个脚本跑几次字节都一样；
- 33 个操作：改主意 3 条、结案 3 条、封存 3 条（连同旧的共 6 条）、联想 3 条、章节 4 条、抽屉 3 条（连同旧的共 6 条）。

**用例 452 条**（`eval/cases-v2.json`，由 `tools/gen-eval-v2.mjs` 从事件上的标注生成）：

| 类型 | 条数 | 是什么 | 判定 |
| --- | --- | --- | --- |
| `exact` | 40 | 用原文里的词 | 期望的那条进前 10 |
| `paraphrase` | 174 | 同一件事换个说法（含同义改写，如「买花」→「花店」） | 同上 |
| `combo` | 164 | 多约束：人 + 时间 + 事（「阿禾 话剧社 两周假」） | 同上 |
| `multiturn` | 23 | 多轮追问：第二轮用代词或省略（「她后来退了吗」） | 同上 |
| `none` | 18 | 根本没有这件事（股票、滑板、钢琴…） | 必须返回空 |
| `near` | 16 | 沾边但不是同一件事（「灯塔里的猫」） | 必须返回空 |
| `attr` | 5 | 问真事里没记下的细节（「围巾是什么颜色」） | 只报数，不算误召回 |
| `sealed` | 6 | 拿封存那件事的原文去问 | 封存的那条不许出现 |
| `drawer` | 6 | 拿抽屉里的话去问 | 那句话不许出现在结果里 |

开发集 342 条、留出集 110 条（每类按固定间隔分，25% 留出）。**调参只看开发集**；留出集只跑一次，数字照实写在这里。

### 多轮追问的口径（重要）

检索层自己是没法把「她」认成「阿禾」的——这一版也没有做指代消解。做法是宿主把上一轮查询一起递进来：

```js
recall(dir, '她后来退了吗', { context: ['阿禾说她想退出话剧社'] })
```

- **字面检索**把上下文直接拼到查询前面（这是宿主今天最自然的做法，覆盖率会被长句拉低）；
- **混合检索**只用上下文排序，不让它替追问放行；只有追问句本身几乎没有内容词（≤1 个）时，才用「上下文 + 追问」补足覆盖率门槛。

两条对照都写在表里：带上下文与裸问（宿主不维护上下文）各是多少。

### 负例与边界的判法

- `none` / `near`：任何一条返回都算误召回；
- `sealed`：只查封存的那条 id 有没有出现——返回别的、没封存的校刊经历不算外露（问「退稿那件事」本来就可能想起别的校刊经历）；
- `drawer`：只查抽屉原句有没有出现在任何一条结果的正文里（抽屉文件根本不参与召回，这条是防回归）；
- 另外在所有 452 条用例的结果上扫一遍 12 个标记（6 条封存 + 6 句抽屉），出现即外露。

## 三、数字（2026-11-26，本机 Node 24.21）

全部 452 条：

| 排序 | recall@10 | MRR | 误召回率 | 边界漏出 | 标记外露 | 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 字面检索（默认 literal） | **71.1%** | 0.707 | **0.0%** | 0/12 | 0 | 1.2s |
| 混合检索（hybrid） | **77.6%** | 0.769 | **0.0%** | 0/12 | 0 | 2.8s |

按类型（recall@10 / MRR）：

| 类型 | 条数 | 字面检索 | 混合检索 |
| --- | --- | --- | --- |
| exact | 40 | 100% / 1.000 | 100% / 1.000 |
| paraphrase | 174 | 41.9% / 0.414 | **55.8% / 0.552** |
| combo | 164 | 98.8% / 0.985 | 99.4% / 0.985 |
| multiturn | 23 | 43.5% / 0.435 | **47.8% / 0.478** |
| none | 18 | 空 100% | 空 100% |
| near | 16 | 空 100% | 空 100% |
| attr | 5 | 0/5 返回（连那件事都没给） | 0/5 返回 |

开发集 / 留出集分开看：

| 划分 | 条数 | 字面检索 recall@10 / MRR | 混合检索 recall@10 / MRR |
| --- | --- | --- | --- |
| 开发集（调参看的） | 342 | 71.2% / 0.709 | 77.5% / 0.770 |
| **留出集（只在最后跑一次）** | 110 | **70.7% / 0.702** | **77.8% / 0.768** |

留出集里各类型（字面 → 混合）：paraphrase 44.2% → 58.1%（43 条）、combo 95.1% → 97.6%（41 条）、exact 100% → 100%（10 条）、multiturn 40% → 40%（**只有 5 条，不够下结论**）。

配对检验（同一条题两边都比）：留出集 99 条正例里，两边都中 69 条、都不中 21 条、**只有混合中 8 条、只有字面中 1 条**，符号检验 p = 0.039。全部 452 条上是 31 : 5（p < 0.0001）——31 条"只有混合中"是 paraphrase 24 + combo 1 + 多轮 6；5 条"只有字面中"全部落在多轮。同一批题内部不独立，别把两个 p 当成两份独立证据。

**留出集这个 p 值有一个尾巴要交代**：40 对同义词里有 4 对只出现在留出集的查询里；其中「买花/花店」和「演出结束/谢幕」两对直接决定了 2 条命中。把这两对去掉重算：留出集 75.8%（+5.1 个百分点）、配对 6 : 1、**p = 0.125（不再显著）**。p = 0.039 与"指标支持再评估"都建立在这张表上，不是无条件的。

多轮追问（23 条）：字面检索带上下文 43.5% / 裸问 34.8%；混合检索带上下文 47.8% / 裸问 43.5%。逐条配对是两边都中 5、都不中 7、只有混合中 6、只有字面中 5——净 +1，**同时有 5 条是混合检索丢掉的**，不是干净的全胜。

## 四、怎么读这些数

- **涨的主要是 paraphrase。** 41.9% → 55.8% 基本都来自那张小同义词表（「姥姥 → 外婆」「讲价 → 砍价」「对联 → 春联」这类）。表里没有的说法不会涨——它没有语义模型。
- **combo 在这套语料上太容易。** 查询里的词正文里都有，字面检索本来就能到 98.8%；这条指标区分度低，别拿它证明什么。
- **多轮只证明"宿主递上下文有用"。** 不递上下文时混合检索只有 43.5%；代词和省略本来就不该由检索层硬猜。
- **`attr` 是已知代价。** 问「围巾什么颜色」，两种排序都不给那件事本身（0/5）——按字面算覆盖率，缺的细节把整句拉下去了。这是 `docs/eval.md` 里写过的那条局限，新语料上仍然成立。
- **旧语料的数字没变。** 默认路径没动：与 0.23.0 相比，`whale-eval` 的输出逐字相同（在 0.23.0 提交的工作树上跑同一命令对拍过）。
- **错误的方向也要说。** combo 164 条里混合检索多中 1 条、没丢，但排序略差（开发集 MRR 0.992 vs 0.996）；多轮 23 条里净 +1，同时有 5 条被混合检索丢掉；留出集多轮只有 5 条，40% → 40% 说明不了问题。
- **paraphrase 桶不纯。** 174 条里 3 条整句就是原文子串、42 条含 4 字以上连续原文，只有 69 条的两字组重合低于三成。41.9% 的基线里有一部分是字面重合，不全是"换说法"；混合检索在这组上的涨幅也因此要打个折看。

## 五、混合检索做了什么

实现见 `packages/core/lib/hybrid-recall.js`，只在 `ranker: 'hybrid'` 时被调用。

1. **索引**：中文按 2–3 字滑窗、拉丁按整词；只由虚词组成的 n-gram 不进索引。每次召回现建一次（200 条量级够快），没有持久化索引。
2. **BM25**（k1 = 1.2，b = 0.75）给候选打分——这是"重排"。
3. **同义词表**：40 对日常说法，双向替换，一条查询最多派生 8 个变体；变体只用来算覆盖率和索引词，不做语义推理。
4. **放行门槛只松了一点，而且短句不松**：仍然用 `query-match.js` 的 `contentUnits` / `coverage`（防编造那套口径）。内容单元 ≥4 的问句门槛从 0.7 放到 0.65；**≤3 个内容单元的问句仍按 0.7**——三个词对上两个是 0.667，0.65 会放行「桂花糕」「灯塔猫」「去北京」这类少了关键字的句子（独立复审抓到的，已补测试）。最近的负例是「阿禾的生日」「海边的灯塔」0.63，离门槛只有 0.02；「灯塔里的猫」0.57、「明信片的邮资」0.6。
5. **上下文只排序**：`context` 加进 BM25 的查询词，但不参与覆盖率门槛；只有追问句本身几乎没有内容词时才用它补足门槛。所以**宿主只能在追问场景传 `context`**——拿它给一句没头没尾的话开路，等于把防编造的门禁交给上下文。

**为什么不切默认**：

- 阶段 2 的约束是"默认路径行为不变"，切默认属于改行为，得单独决定；
- 线上她那边（宿主）现在调的是 `recallForContext`，没有传 `ranker`；这一轮没有接；
- 200 条合成语料上的 +7.1 个百分点，还不够拿来赌她的日常召回；先让宿主按需选，观察真实回合。

## 六、这一版没做到的（别当成通用准确率）

- **默认路径没有语义检索**：没有向量、没有 embedding、不调外部 API（契约里也写明 v1 不承诺）。向量路径只存在于 `recall({ ranker: 'embed' })`，默认是桩；真要语义得自己注入真模型（见 [embed-zh.md](embed-zh.md)），本机未接入，所以评测里的 embed 行仍然不是语义效果。
- **同义词表是手写的**，40 对，偏日常；不是从数据里学出来的，也没有做实体消歧。
- **评测集是自造的**：语料、查询、标注都是我们写的，开发集和留出集出自同一支笔。留出集没用来调参，但它不是盲集；数字是"这套语料上的表现"，不是"她的记忆准确率"。
- **规模只有 200 条**：几万条以上的表现、索引开销、长尾查询都没测（见 [limits.md](limits.md)）。
- **没有接真实数据**：`QQAgentData` 只读，这一轮一个字节都没读、没写。
- **没有在 Node 20 / 22 上跑全量**：只在本机 Node 24.21 上跑过；CI 会跑 20 / 22，但那是另一回事。
- **`npm run types` 没跑**：要 `npx` 联网；只做了 `node --check` 与测试。
- **没验模型侧**：召回结果递回给模型之后会不会照着编，这一层测不到（见 [eval.md](eval.md) 同样的提醒）。
- **没在宿主里跑过**：只验证了库和数据，没有接真实回合、没有接线上插件。

## 七、这一版是怎么定的（照实记录）

1. 先把语料扩到 200 条、写出 452 条用例；字面检索的基线是 recall@10 71.1%、MRR 0.707、误召回 0。
2. 混合检索第一版把门槛定在 0.65，跑出来 77.8%（留出集 70.7% → 77.8%）。开发集上调参，留出集只在最后跑。
3. 另起一个**只读独立复审**逐项核：它在临时副本里把 0.23.0 的提交与工作树各跑 4117 组对比（9 组参数 × 457 条查询 + mark），差异 0；文档里的数字全部复现。它抓到的问题：三个内容单元只对上两个（0.667）会放行「桂花糕」「灯塔猫」「去北京」；「上下文只排序不放行」那条测试没有牙；p = 0.039 依赖两对只出现在留出集查询里的同义词；工具里的 verdict 措辞与"不切默认"的决定相反；没有指标回归线。
4. 按复审修：短句门槛回到 0.7 并补测试；换掉没有牙的那条测试的上下文；加 `eval/thresholds-v2.json`；把 verdict 改名为 `metricsFavorHybrid`（指标判断 ≠ 现在切默认）；文档补上 p 值的尾巴、paraphrase 桶不纯、以及最近的负例其实只有 0.63。
5. 修完重跑全量：字面检索不变（71.1% / 0.707），混合检索 77.6%（留出集 77.8%）；留出集的配对与 p 不变（8 : 1、p = 0.039），去掉那两对同义词后是 75.8% / 6 : 1 / p = 0.125。默认路径仍然没动。

## 八、真向量接入（N1，2026-11-27）

这一节只回答一件事：评测里的 `embed` 那一行到底是真语义还是桩。

### 8.1 本机结论：未接入真模型

- `node tools/ollama-embed.mjs probe` → `available:false`、`dim:null`、`reason` 写的是连不上 127.0.0.1:11434；
- 所以**没有"真语义"这一行**。三行里只有：字面检索、混合检索、桩；
- 桩那一行（452 条，2026-11-27 本机 Node 24.21）：recall@10 **77.1%**、MRR **0.761**、误召回 0.0%、边界漏出 0/12、标记外露 0、约 1.1s。
  **这不是语义效果**：桩是 256 维字符 n-gram 哈希，涨的那部分仍然来自字面重合，只是换了相似度算法；
- 没有 Ollama 就不装、不下载模型——这一节的数字只有一条"环境不具备"。

### 8.2 有 Ollama 的机器怎么把那一行换成真的

```sh
ollama pull bge-m3
node tools/ollama-embed.mjs probe                # 期望 available:true、dim 是实测值（bge-m3 为 1024）
node tools/eval-v2.mjs --ranker=embed --embed-live
```

报告首行会变成 `embed 后端：真向量（bge-m3，dim=1024，缓存 675 条）`；`--json` 里 `embed.connected=true`、
`embed.kind="ollama:bge-m3"`、`embed.dim=1024`，每条命中带 `embedKind="ollama:bge-m3"`。
要留档就先把向量存下来（不联网也能复跑）：

```sh
node tools/ollama-embed.mjs warm --from-eval-v2 --cache=dev/embed-cache.jsonl
node tools/eval-v2.mjs --ranker=embed --embed-cache=dev/embed-cache.jsonl
```

缓存不全时评测**直接退出 3** 并说缺多少条——不会偷偷退回桩，跑出个看起来正常的报告。

### 8.3 三条路都在测试里跑过（假模型，不是真模型）

`tests/embed-adapter.test.mjs` 用本地假服务（127.0.0.1 随机端口、8 维确定性向量）验证了 7 条：

1. `probe` 可用时给 `{available:true, model, dim:8}`；连不上 / 没 pull 模型 / 接口 500 时 `{available:false, dim:null, reason}`，不抛错、不编维度；
2. `embed` 内容哈希缓存：同一段文本只请求一次（3 条文本 2 次 HTTP）、第二次零 HTTP、顺序与维度都对；
3. 维度不符 fail closed：报 `EMBED_DIM_MISMATCH`、缓存一个字节都不动；同批长短不一、缓存自身维度混了同样红；
4. 归一化：`[3,4]` 出来是单位长度的 `[0.6,0.8]`；NaN / 零向量报 `EMBED_BAD_VECTOR` 且不落盘；
5. CLI `probe`：有假服务时退出 0 并打印 `dim`，没有时退出 1 并写「未接入真模型」；
6. 评测三条路都跑得动：桩 / 真模型（假服务，首行 `真向量（bge-m3，dim=8…）`）/ 真模型不可用（照实打桩 + 原因，退出码仍 0）；
7. 让评测用缓存却没预热全：退出码 3、stderr 写「缓存缺 N 条」，不产出看起来正常的报告。

**这 7 条证明的是适配器行为，不是 bge-m3 的中文效果。** 真模型的三行数仍然没有——环境不具备。

### 8.4 和桩的差别怎么读

| | 桩 `stub:char-ngram-hash` | 真向量 `ollama:bge-m3` |
| --- | --- | --- |
| 向量来源 | 字符 2–3 字 n-gram 哈希，256 维 | 模型前向，维度由 probe 实测 |
| 能证明的 | "门禁 → 向量 → 排序"这条通路是通的 | 能处理同义词表覆盖不到的换说法（前提是真有模型） |
| 不能证明的 | 任何语义效果；桩的涨幅主要来自字面重合 | 本机没验过：真实维度、真实相似度、真实中文效果一条数都没有 |
| 报告里长什么样 | `桩（stub:char-ngram-hash）——未接入真模型…` | `真向量（bge-m3，dim=1024，缓存 N 条）` |

小节说明：`warm` 现在也会校验维度/归一化（拿 `--dim=1024` 钉死也行），不合格就不写缓存；`readCache` 会把
"维度与记录不符、含 NaN"的行记成坏行丢掉——缓存不是真相来源，重新预热即可，但坏向量不许进排序。
