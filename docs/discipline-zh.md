// > 用意：把"我们说过要守的规矩"按**能不能被机制检查**分档，免得把"我们希望"写成"系统保证"。
//
// 三档怎么分：
// - **可数**：有测试 / 断言 / 工具守着，坏了 CI 会红，或者 `doctor` 会报。说"有机制"是真的。
// - **半可数**：有信号、有阈值、有评测，但样本有限、判据软——只能抽查 + 定期复核，不能当成保证。
// - **不可数**：机制完全管不到，只能靠写下来、靠人自觉。**写在这一档的，谁都不许当成承诺。**

## 二、半可数（有信号、有阈值，但要抽查）

| # | 规矩 | 机制在哪 | 为什么只是半可数 |
| --- | --- | --- | --- |
| 8 | 召回要"召得回、别乱召" | `tools/eval-v2.mjs` 452 条用例 + 门槛（recall@k / MRR / 防编造覆盖率） | 语料是我们自己写的；真实对话分布不同，数字只说明"没退化" |

## 三、不可数（机制管不到，只能靠自觉与写清楚）

| # | 规矩 | 为什么管不到 | 能做的只有 |
| --- | --- | --- | --- |
| 12 | 她说的到底是不是真的 | 库只保证"她当时这么说过"，不判断真假 | 记录留原话与时间；让她自己纠 |
| 13 | 那句话当时的分量 | 情绪、语气、场合都不在 JSONL 里 | 别用自己的理解覆盖原话 |
| 14 | 这一刻该不该提 | 场合判断没有可测的口径 | 宁可不说；说了要能收回（封存/撤回） |
| 15 | 说出口的后果 | 库不接触现实 | 破坏性操作留痕（墓碑 + 审计），让人能事后核 |
| 16 | 别人的信任 | 不是数据问题 | 不承诺、不吹数字、不把希望写成保证 |
| 17 | 我们有没有把"没验过"写成"验过" | 没有机制能自动判定 | 回报里必须有一行「没验什么」；缺这一行就当没交 |

## 四、用法

- 写新功能时**先给它归到某一档**：可数就补测试，半可数就补评测/阈值并写明样本，不可数就写进第三节、别在文档里写成承诺。
- 对外文档只允许把**可数**的说成"保证"；半可数写"有评测/有门槛"；不可数写"靠自律"。
- 这一页本身也受第 17 条约束：条目里写的"机制在哪"必须是真跑得起来的东西，不是愿望。
