# 上限与不保证

> [English](en/limits.md) · 中文（本页）

这份文档写清楚：它能撑多大、做不到什么、哪些是故意的。不想在 README 里写成"企业级"，也不想让你踩了坑才发现。

## 规模

实测（Windows 11 x64，Node v24.21.0，2026-11-16）：

| 经历条数 | `loadAll` 中位数 | `recall` 中位数 |
| --- | --- | --- |
| 2,000 | 4.9 ms | 13.9 ms |
| 10,000 | 21.8 ms | 68.3 ms |

复现命令（热身 3 次，取 5 次中位数；样本是 30~50 字正文 + 一句想法，1/4 带原文锚）：

```sh
node tools/bench-recall.mjs --n=10000
```

- 每次召回都会**读全量**、逐条扫描。没有索引、没有向量、没有分片。
- 一条经历约 0.5 KB，10,000 条约 5 MB。
- **事件文件只增不减**：每想起一次多一行 `recall-events.jsonl`，每改一次主意多一行 `later-events.jsonl`，每做一次「想通/暂放/再拾起」多一行 `unfinished-events.jsonl`，每封存或解封一次多一行 `seal-events.jsonl`，每连一对事、每开/改/结束一个章节各多一行 `link-events.jsonl` / `chapter-events.jsonl`（后面几个量都很小）。上面的表只算了经历本身，长期使用要把这几份也算进去。
- 几万条会开始明显变慢；到十万级，这个实现就不合适了。

**故意的**：先保"原文不可改"和"没有记录就说没有"，再谈吞吐。要上十万级，宿主应当自己加索引（见 [composition.md](archive/composition.md)），而不是把向量塞进这里。

## 存储与加密

- 明文 JSONL。**没有内置加密**，能不能加密取决于磁盘（BitLocker / FileVault / 全盘加密）。
- 任何能读这个目录的本机进程都能读全部记忆。多用户机器上，靠系统账户隔离。
- 没有多设备同步、没有云端备份。搬家靠复制整个目录或 `export`。

## 能力层验证，不是文件检查

`doctor` 不是看“目录在不在”，是在临时目录里真的走一遍：

```
写入 → 后记 → 结案 → 召回
导出 → 导入 → 读回
事件文件逐行解析
醒来白名单：私聊放行、群聊拦截
```

```sh
node adapters/cli/memory-cli.mjs doctor
```

`ok: true` 才说明这套代码在当前机器上真的能写能读。升级前后各跑一次；换机器也先跑它。

**关于索引**：本项目故意不做内置索引，原文是唯一真相。如果宿主需要索引（比如 FTS、向量），应当**在写入时旁路生成**，并且保证索引删掉后能从原文重建——索引永远不是来源，只是加速。任何“索引里有、原文里没有”的状态都算 bug。

## 提示词 overlay 是持久的（最特别的一条）

`prompt set` 写进去的内容会**每一轮都生效**，直到被改回。所以：

- 只允许可信的调用方（宿主自己、或在明确授权下的角色）改提示词，不要把用户的自由文本原样拼进去。
- 写之前先 `prompt get` 看当前版本，写完 `prompt history` 留底。
- 发现不对，立刻 `prompt revert --version <上一个版本>`。
- 提示注入一旦写进 overlay，不会随会话结束消失。这是本项目最容易被忽视的安全边界。

## 删除

**支持整库删除**，命令：

```sh
node adapters/cli/memory-cli.mjs purge --data <数据根目录>          # 只列出，不删
node adapters/cli/memory-cli.mjs purge --data <数据根目录> --yes true  # 真删
```

它只处理数据根目录下的这些位置：

- `plugin-data/biomimetic-memory/`（经历、日记、事件、设置、提示词 overlay）
- `plugin-data/biomimetic-memory.pre-import-*`（`import --force` 留下的备份）
- `backups/self-experience-pre-{later,recall}-events-*.jsonl*`（迁移备份）

**不处理**：`export` 的输出目录。导出包在你指定的地方，`purge` 不替你删，需要自己清理。

**`.pre-import-*` 是什么**：`import --force true` 不覆盖旧目录，而是把它**改名**成
`plugin-data/biomimetic-memory.pre-import-<时间>`，再装新目录。那份旧目录就**留在盘上**——
里面有正文、后记、事件，跟记忆目录一样是明文。

- 它**不会被自动清理**：没有任何定时任务或库内 API 会碰它；`eraseExperience` 也不碰（擦除只动当前记忆目录，
  见下面「历史副本不追溯」那条）。
- 要清它有两条路：① `purge` —— 上面那张清单里就有它，但那会连记忆目录一起删；
  ② 只想删这一份就**手动删目录**（前缀固定，`ls plugin-data/` 一眼能认出来）。
- 恢复演练里的用法（确认一切正常、过几天再清）见 [`archive/runbook.md`](archive/runbook.md)。

- **单条物理删除自 v1.1 起提供**：`eraseExperience(dir, { id, reason, actor })` 把这一条连同关联事件删掉，只留一块墓碑（id / 时间 / 原因 / 删除前内容的哈希，不含正文）。见 [擦除与审计](erase-audit-zh.md)。这是破坏性操作：先备份，只由宿主在「她本人或 Leo 明确要求」时调用。
- **整库删除**仍是 `purge`（见上）。
- `then` 故意不可改：能改就能洗记忆，"自传"也就不成立了。所以"被遗忘权"和 append-only 的冲突这样解：**改内容永远不许；整条撤回允许，但必须留墓碑**。备份 / 快照里的历史副本**不追溯**。
- **没说出口的抽屉**（0.15 起）同样是明文、同样跟着备份走；"丢掉"只是她自己不再看到，原文仍在文件里。抽屉里的东西没有 `exp_` id，撤不到；要真的抹掉，仍然只能 `purge` 或手工处理文件。
- **封存不是删除**（0.13 起）：`seal --id` 让她不再被这件事主动提醒——不被召回、不进醒来块、别的回想引用它时不露内容；但原文、后记都还在磁盘上，`read --id` 点名仍能读到，导出包里也有。封存是她的选择，不是给用户的隐私删除；要真的抹掉正文，用 `eraseExperience`（`seal-events.jsonl` 里那条状态记录会留着，见擦除文档）或整库 `purge`。

## 写入会不会自动建目录

**会，而且所有写入口都自动建**（`mkdirSync(..., recursive: true)`，父级一起建）。写经历、后记、
封存 / 解封、想起、结案、联想、人生章节、审计、墓碑、没说出口的抽屉，全都如此；`eraseExperience` 也会。
理由是宿主第一次使用时不用先分清"哪个文件属于哪个模块"——目录不存在只表示"还什么都没有"，
不表示"出错"。**这是允许的行为，不是漏洞。**

三条边界（`tests/mkdir-behavior.test.mjs` 逐条验过）：

- **读不建**：`loadAll` / `recall` / `currentView` / `book` / `exportMemory` / `badLines` 对不存在的目录
  返回空（0 条 / `null` / 空书），**不会**把目录建出来，也不会顺手建库。
- **目标错了就不碰**：`reviseExperience` / `setSealed` / `setUnfinishedState` / `linkExperiences`
  指向不存在的记录时，在写任何东西**之前**就返回 `{ok: false}`——不会留下空目录、也不会留下半条事件。
- **两个"给不存在的目标也留了东西"的例外**（都是故意的，写在这里免得当成 bug）：
  `markRecalled(dir, id)` 不做存在性检查（孤儿想起事件在读的时候被忽略），会建目录并追加一条
  `recall-events.jsonl`；`eraseExperience` 撤回一个根本不存在的 id 会返回
  `{ok: true, alreadyGone: true}`，但**目录已经被建出来**（空目录，里面没有文件）。
  要干净就别对空目录调 `erase`。

## 作品稿本

- 单版正文上限 **16 KiB**，每件作品最多 **2000 版**；到顶是**拒绝写入**（`version_limit`），不会悄悄裁掉旧版。
- 每件作品一个只追加的 JSONL；写入持有目录锁（mkdir + owner.json + 心跳），并 `fsync`。同一台机器上按 pid 判活，活着的持有者不会被抢锁。
- 读不懂的行会跳过并计数（`corrupt`）；整份都读不出来时返回 `unreadable`，**不会**当成"她还没写"。
- `asOf` 比较的是调用方写进去的 `at`：时钟回拨会让版本顺序看起来错位，这不在库的修正范围内。

## 并发

实际行为：

- `addExperience` **不加文件锁**，用操作系统的追加写（`a+`）。多进程同时写不丢行的前提是每次都整行追加；它不是事务，不能保证顺序。
- `later-events` / `recall-events` 的追加**走文件锁**（mkdir 互斥）；锁那一层的 mkdir 遇到 Windows 的 EPERM 会重试，**rename 不重试**。
- `self-settings` 和 `prompt` 的写是"锁 + 临时文件 + rename"。
- `eraseExperience` 只拿一把 `erase.lock`（目录锁），重写经历 / 事件文件走 `writeFileAtomic`
  （临时文件 + rename），**不抢**各事件文件自己的 `.lock`——擦除期间只持自己的锁，避免和事件写入路径
  互相等锁（`tests/erase-lock-scope.test.mjs` 验过：别的进程正持有某个事件文件的锁时，擦除照常完成）。
  代价是并发下擦除可能覆盖对方刚追加的那一行；仍然在「单写者」假设里（契约第六节）。
- `export` / `import` **不加锁**：宿主还在写的时候导出，可能拿到一个文件新、一个文件旧的快照；导入时宿主还在写，也没有人拦。

导入会先在目标旁的 `.import-stage-*` 目录里准备完整副本，再替换目标。复制或校验失败时原目录保留；替换报错时尝试还原 `.pre-import-*` 备份。两步改名之间会写 `<memDir>.import-journal.json`（含 target/backup/stage/phase），下次 `import` / `export` 会先调 `recoverImport()`：崩在两次 rename 之间 → 自动把 `.pre-import-*` 改回记忆目录并清 stage/日志；新目录已装好但日志没删 → 保留新目录与备份、只清日志。**通常不需要人工干预**；只有自动恢复失败时才保留 journal、备份与暂存目录并报错，按 journal 的 `backup` 字段人工改名回去，确认内容后再清理。这套流程没有跨文件系统事务或断电持久性保证。

因此：**导出、导入、purge 之前先停掉宿主**，或者接受快照可能偏几秒。不要让两个宿主进程同时写同一个目录。

## 召回语言

- 分词和停用词是按中文调的：中文按相邻两字切，常见虚词不参与匹配。
- 英文只做了最基本的支持：按整词、小写匹配，虚词过滤；不做词干、不做同义。
- 需要真正的多语言语义召回，请把检索交给宿主（见 [composition.md](archive/composition.md)）。

## MCP 适配器

- MCP 客户端算"受信的本机进程"：连上的客户端能读写全部记忆（抽屉除外，除非 `--owner true`）。不要把它接到别人能发消息的地方，除非宿主先校验调用者。
- 故意不提供导入、导出、删除、改提示词、改设置；这些只能走 CLI。
- 只有 stdio 传输，不开端口。要远程用，请在宿主那一侧自己解决鉴权，本项目不提供 HTTP 服务。

## 不保证

- 不保证跨版本自动升级。改格式会写迁移脚本，但迁移前请先备份；迁移可以回滚，回滚会保留事件。
- 不保证"永远能读"。文件被手工改坏、事件被删、两个版本同时写同一个目录，都可能读不出来。
- 不保证角色"像人"。它只保证：当时写的没有被覆盖，后来的想法能追加上去，找不到记录时不编。

## 什么时候不该用它

- 需要语义检索、模糊匹配、跨十万条毫秒级召回
- 需要中文以外的多语言召回（英文只是够用）
- 需要多人协作、权限分级、审计日志
- 需要合规级加密与单条删除（GDPR 那类）
- 需要开箱即用的聊天记忆中间件

这些场景请用专门的记忆基础设施；whale-memory 只做"人格层"那一小块。不够用不是 bug，是边界。
