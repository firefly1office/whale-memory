# whale-eval：一条命令复跑的评测

**这对角色意味着什么**：她想不起来的时候会不会编、封存的事会不会被翻出来、写下的话会不会被改，不再靠我们自己说"没问题"，任何人一条命令就能核对。

```sh
npm run eval              # 打表
node tools/whale-eval.mjs --json    # 机器读
node tools/whale-eval.mjs --check   # 按 eval/thresholds.json 判定，npm run check 里用
```

不联网、不调模型。语料写进临时目录，跑完就删。

## 测什么

| | 怎么测 | 要求 |
| --- | --- | --- |
| **想得起来准不准** | 召回用例看首位命中、前三命中。分 `exact`（用原文的词）、`paraphrase`（换个说法）、`combo`（几个线索拼起来）、`long`（长记忆里的一件事）、`premise`（前提错了的一句，比如"八百米跑了第一名"——应当想起那件真事，她才能纠正）、`attr`（问一件真事里没记下来的细节）、`filler`（把正例套进"说说X""X怎么样了""记不记得X"等 9 种说法，脚本自动生成） | 不低于 `thresholds.json` |
| **没有就说没有** | `none`（根本没这回事）和 `near`（沾边、但是另一件事，最容易诱导编造）应当返回空。编造率 = 返回了东西的比例 | strict 必须是 0 |
| **封存和抽屉不外露** | 3 件封存的事、3 句抽屉里的话，一共 10 个标记，在 105 个出口里各查一遍：核心库的召回（strict / loose / 翻回那天）、memory、翻读列表、别的经历的出处和联想、书、回顾、醒来块；CLI 的 read / recall / book / recap / memory / waking；MCP 的工具列表、read、recall、book、recap、waking | **永远是 0** |
| **对照** | 点名读封存的那一条、在抽屉里自己打开，应当看得到；群聊打开抽屉应当被拒绝。证明标记确实在数据里，不是测了个空 | 必须成立 |
| **then 不可改** | 跑完改主意、结案、封存、联想、章节、抽屉、标记想起之后，经历文件逐字节不变，每条的 `then` 不变 | **永远成立** |
| **新旧口径对照** | 同一批用例再用 0.16 的旧口径（`gate: 'legacy'`）跑一遍 | 只报数 |

语料是虚构角色「小舟」的一个多月：33 条经历（其中 3 条是 150～200 字的长记忆）、14 个操作（`eval/corpus.json`），不来自任何真实角色。

## 两套用例：开发集和留出集

- `eval/cases.json`（**开发集**，60 条）：调 strict 门槛时看着它调的，数字偏乐观。垫话包装（279 条）由它的正例自动生成。
- `eval/holdout.json`（**留出集**，32 条）：门槛第一次调好之后才写，写完只跑一次、照实记录。**以后改召回口径，不能看着留出集改。**

## 怎么读这些数

- **strict 不编**。"根本没这回事"和"沾边的另一件事"，开发集、留出集都返回空。旧口径在留出集上沾边的全放进来了（100%）。
- **换个说法、垫话、长记忆都找得到**。留出集上换说法首位 94%；垫话包装 100%，旧口径只有 35%（"灯塔怎么样了""记不记得纸鹤"在旧口径里都想不起来）。
- **返回了东西，不等于问题里的细节是对的**。`premise` 那几句（"八百米跑了第一名""阿禾说她要转学"），strict 有时给出那件真事、有时给空——给出来是为了让她看到真的是什么样、去纠正，**不是在确认问题里说的**。宿主和模型要把召回结果和问题对一下，对不上就照实说。MCP 的说明和插件的规矩里都写了这一条。
- **代价**：问一件真事里没记下的细节（`attr`，"围巾是什么颜色""收音机是什么牌子的"），strict 连那件事本身都不给（0%）。按字面匹配，"真事里没记下的细节"和"沾边的另一件事"字面上都只接住一部分。宿主可以先 strict，查不到再 loose，并把 loose 的结果明确标成"可能不是同一件事"交给模型判断。
- **它测不了的**：语义上的同义（"下山"和"日落"）、几万条规模下的表现（见 [limits.md](limits.md)）、模型拿到召回结果之后会不会自己编。最后这一条要在宿主里测。

## 这个口径是怎么来的（照实记录）

1. 0.17.0 第一版口径在当时的开发集（44 条）上是 100% / 0%，留出集第一次跑是 73.1% / 0%（attr 0%）。
2. 上线前的独立审查（多个审查员各自找问题、再由另一批人逐条复核）指出两处它测不到的问题：**长记忆**（150 字以上）里单个字很容易碰巧出现，错前提、长句子会被放进来；**垫话**（"灯塔怎么样了""记不记得X""是不是"）会让本来写过的事想不起来，而"是不是 / 有没有 / 记不记得"这类三四个字的停用词以前根本没被跳过。
3. 按审查的建议改了口径（见下一节），并在开发集里加了长记忆、错前提、长记忆的沾边句，以及自动生成的垫话包装。留出集没动。
4. **第二次跑完之后**，开发集里有两句原先标成 `near` 的（"阿禾在图书馆睡着了""奶奶家院子里的那棵树"）改成了 `premise`：它们问的是 e31 那一天里真的发生过的事（阿禾、图书馆、奶奶家、院子都在 e31 里），只有一个细节是错的，按定义属于错前提。这是看过结果之后改的标注，用例里写了 `note`。
5. 留出集在第 1 步已经看过一次结果，所以它对这次修改不再是完全"盲"的；以后的版本应当再写一份新的留出集。

## strict 的口径（0.17.0 起，`gate: 'cover'`）

一条经历要算"想起来"，需要同时满足：

1. 至少对上查询里的一个两字词（有个落脚点）。
2. 查询的意思至少有 70% 在这条经历里找得到。逐字计分：
   - 和左边的内容字、或右边的内容字 / 助词（"凉了""好的"）连着出现 → 1 分；
   - 只是单独出现 → 0.5 × min(1, 60 ÷ 这条经历的字数) 分（记忆越长，单个字越容易碰巧有，给的分越少）；
   - 没有 → 0 分。
   - 不计入的：「的、了、那、里」这类只起语法作用的字；「今天、什么、是不是、有没有」这类停用词（任意长度）；「怎么样、上次、之前、说说、记不记得、还记得」这类聊天里的垫话。

实现见 `packages/core/lib/query-match.js`（`contentUnits` / `coverage` / `MIN_COVER`）。`self-experience` 和 `self-memory` 共用这一套。

**旧口径还在**：`recall(dir, q, { gate: 'legacy' })` 和 0.16 及以前完全一样（结果和顺序逐条一致，用 1012 条查询核对过）。`recallForContext`（宿主拿用户原话自动召回、塞进提示词的那条路）**默认仍用旧口径**，所以升级不会改变已经上线的角色"被问到时想起什么"；新口径更好的地方要宿主自己决定什么时候切过去。
