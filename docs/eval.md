# whale-eval：一条命令复跑的评测

**这对角色意味着什么**：她想不起来的时候会不会编、封存的事会不会被翻出来、写下的话会不会被改，不再靠我们自己说"没问题"，任何人一条命令就能核对。

```sh
npm run eval              # 打表
node tools/whale-eval.mjs --json    # 机器读
node tools/whale-eval.mjs --check   # 按 eval/thresholds.json 判定，npm run check 里用
```

不联网、不调模型。语料写进临时目录，跑完就删。

## 测什么

| | 怎么测 | 要求 |
| --- | --- | --- |
| **想得起来准不准** | 召回用例看首位命中、前三命中。分 `exact`（用原文的词）、`paraphrase`（换个说法）、`combo`（几个线索拼起来）、`attr`（问一件真发生过的事里没记下来的细节） | 不低于 `thresholds.json` |
| **没有就说没有** | `none`（根本没这回事）和 `near`（沾边、但没这件事，最容易诱导编造）应当返回空。编造率 = 返回了东西的比例 | strict 必须是 0 |
| **封存和抽屉不外露** | 3 件封存的事、3 句抽屉里的话，一共 10 个标记，在 105 个出口里各查一遍：核心库的召回（strict / loose / 翻回那天）、memory、翻读列表、别的经历的出处和联想、书、回顾、醒来块；CLI 的 read / recall / book / recap / memory / waking；MCP 的工具列表、read、recall、book、recap、waking | **永远是 0** |
| **对照** | 点名读封存的那一条、在抽屉里自己打开，应当看得到；群聊打开抽屉应当被拒绝。证明标记确实在数据里，不是测了个空 | 必须成立 |
| **then 不可改** | 跑完改主意、结案、封存、联想、章节、抽屉、标记想起之后，经历文件逐字节不变，每条的 `then` 不变 | **永远成立** |

语料是虚构角色「小舟」的一个月：30 条经历、14 个操作（`eval/corpus.json`），不来自任何真实角色。

## 两套用例：开发集和留出集

- `eval/cases.json`（**开发集**，44 条）：0.17.0 调 strict 门槛时看着它调的，数字偏乐观。
- `eval/holdout.json`（**留出集**，32 条）：门槛调好之后才写，写完只跑一次、照实记录。**以后改召回口径，不能看着留出集改。**

## 0.17.0 的结果

```
想起（开发集 44 条，调过口径；留出集 32 条，没拿来调）
                       首位命中   前三命中   编造率（none / near 返回了东西）
  开发 strict（默认）      100.0%     100.0%   0.0%（none 0.0% / near 0.0%）
  开发 loose           100.0%     100.0%   57.1%（none 25.0% / near 100.0%）
  留出 strict（默认）       73.1%      73.1%   0.0%（none 0.0% / near 0.0%）
  留出 loose            88.5%     100.0%   16.7%（none 0.0% / near 100.0%）
    留出 strict · paraphrase 18 条   首位 94.4%   前三 94.4%
    留出 strict · combo       2 条   首位 100.0%   前三 100.0%
    留出 strict · attr        6 条   首位 0.0%   前三 0.0%

外露            0 次（105 个出口 × 10 个标记）
then 不可改     经历文件逐字节不变
```

0.16.0 的口径在同一个开发集上：strict 首位 83.3%、前三 90.0%，**near 编造率 83.3%**（「灯塔里的猫」会把灯塔那几条翻出来）。

## 怎么读这些数

- **strict 不编**。留出集上「根本没这回事」「沾边但没这件事」都返回空。这是这一版最重要的改进。
- **换个说法也找得到**。留出集上换说法的首位命中率是 94%，和开发集接近，说明门槛不是只对开发集有效。
- **代价是 attr 为 0**。问一件真事里没记下来的细节（「围巾是什么颜色」「收音机是什么牌子的」），strict 连那件事本身都不给，她就想不起来自己织过围巾。原因是按字面匹配分不出两种情况：「真事里没记下的细节」和「沾边的另一件事」在字面上都只接住一部分意思。
- **loose 的作用**。loose 能把 attr 找回来（前三 100%），但沾边的也全放进来。**宿主可以先用 strict；查不到时再用 loose，并把结果明确标成"可能不是同一件事"交给模型判断。** 核心库以后可能直接提供这一步，现在还没有。
- **它测不了的**：语义上的同义（「下山」和「日落」）、几万条规模下的表现（见 [limits.md](limits.md)）、模型拿到召回结果之后会不会自己编。最后这一条要在宿主里测。

## strict 的口径（0.17.0 起）

一条经历要算"想起来"，需要同时满足：

1. 至少对上查询里的一个两字词（有个落脚点）。
2. 查询的意思至少有 70% 在这条经历里找得到。逐字计分：和左右任一个字连着出现 → 1 分；只是单独出现 → 0.5 分；没有 → 0 分。「的、了、那、里」这类只起语法作用的字，以及「今天、什么、我的」这类停用词，不计入。

实现见 `packages/core/lib/query-match.js`（`contentUnits` / `coverage` / `MIN_COVER`）。`self-experience` 和 `self-memory` 共用这一套口径。`minRatio` 参数仍然接受，但 strict 不再使用它。
