## 〇、稳定面（1.0 承诺不破的部分）

这一节是 1.0 相对 0.x 唯一新增的实质内容：把"宿主能据此写代码"的东西，和"我们改了你不用知情"的东西，
明确切开。判据只有一条——**宿主按这一节写下的代码，1.0 内不许被我们的改动弄坏**。

### 0.1 稳定面（承诺不破）

| 面 | 具体是什么 | 条款 |
| --- | --- | --- |

这四样**不是**"尽量"：1.0 内它们的破坏等价于破坏性变更，只能走第五节的 v2 通道。

### 0.2 内部实现可变（不在承诺里）

下面这些**随时会变**，宿主不许依赖它们（`§0.2-1`）：

- 模块怎么切文件、内部函数叫什么、参数默认值在代码里怎么摆；
- 返回值里**契约没点名**的字段（多出来的字段可能消失或改名）：例如 `removed.*` 的具体键、
  `refsInfo` / `citedBy` 这类派生视图的条目形状、`viewAsOf` 之外的时间戳；
- 合并逻辑怎么实现（后记怎么排序、想起次数怎么缓存、索引文件叫什么、`*.lock` 文件名）；
- SQLite 的表结构、索引、`sources` 表的列（迁移工具和读路径自己对齐，宿主别直连库）；
- 日志 / 报错文案的措辞、控制台输出、性能数字；
- `internals` 这类带 `internals` 名字的导出（它们明确不是 API）。

### 0.3 一句话判据

宿主问自己："这段代码坏了，是**我们的契约**破了，还是我用了不该用的内部细节？"
——答案在 0.1 表里找。找不到，就是内部细节。

## 一、根原则

1. **记录不可变。**（`§1-1`）一条经历写进去之后，那一行永远不改。改主意、封存、想起次数、没弄完后来怎么样了——全部是**独立事件**，追加到各自的事件文件。
2. **一条记录可以被整条撤回（`erase`）。**（`§1-2`）撤回后，正文与关联事件一并删除，只保留墓碑：id、撤回时间、原因、删除前内容的哈希。
3. **墓碑不含正文，也不可用于恢复。**（`§1-3`）它只说明"这条存在过、被撤回了"。
4. **封存不是删除。**（`§1-4`）封存只是"别再主动提起"；数据还在，可以解封。删除是另一件事——单条走 `erase`，整库走 `purge`（见第六节与[擦除与审计](erase-audit-zh.md)）。

## 二、数据契约

### 2.1 文件布局

```
<memory-dir>/
  self-experience.jsonl        经历，一行一条，只追加
  later-events.jsonl           改主意 / 回头想
  seal-events.jsonl            封存 / 解封
  recall-events.jsonl          想起次数
  unfinished-events.jsonl      没弄完的事后来怎么样了
  unsaid.jsonl                 没说出口的抽屉（独立空间，永不自动注入）
  tombstones.jsonl             撤回墓碑（v1.1 起；{v, id, ids, at, reason, actor, hash}，不含正文）
  audit.jsonl                  审计（v1.1 起；{at, actor, action, ids, note}，只记 id 与动作）
  fact-events.jsonl            事实键事件（v1.2 起、可选；只在调用 factKey.setFact 时出现）
```

（`§2.1-1`）上面这八个文件名是契约：宿主可以按名字找、按字节备份，库不会换名字。
所有文件都是 JSONL（一行一个 JSON）。

（`§2.1-2`）解析方必须容忍**最后一行没有换行**，以及**坏行**——坏行要报出来，不能当空。

（`§2.1-3`）可选（阶段 1 起）：`memory.sqlite`——同一份数据换一个容器（见 [存储后端](storage-backend-zh.md)）。
记录与事件的 JSON 形状和上面的 JSONL 逐条相同；**迁移是叠加，JSONL 不删、不改**。

### 2.2 记录（`self-experience.jsonl`）

字段定义以 [`schemas/record.v1.json`](../schemas/record.v1.json) 为准。要点：

| 字段 | 契约 | 条款 |
| --- | --- | --- |
| `id` | `exp_` 前缀，**不透明**。宿主不许解析、不许按格式拼 id、不许复用。 | §2.2-1 |
| `at` / `day` | `at` 是写入时刻（ISO 8601），`day` 是本地日。按"那一天"检索只看 `day`。 | §2.2-2 |
| `then.*` | 写入那一刻的原样：`text` 必填（≤2000），其余可选。**任何系统都不许替她改写 `then`。** | §2.2-3 |
| `later` | 写入时恒为空数组。后续变化只进事件文件，**不回写**。 | §2.2-4 |
| `sealed` | **不是记录字段**。封存状态由 `seal-events.jsonl` 推出；记录本身不含它。 | §2.2-5 |

（`§2.2-6`）落盘的那一行必须符合 `schemas/record.v1.json` 的 `required` 与类型；schema 里 `additionalProperties: false`，
所以**新增字段必须同时改 schema**——这是"只加不减"在记录上的落法。

### 2.3 时间语义（as-of）

- （`§2.3-1`）`read({ asOf })` 返回**那一刻已经存在、且当时还没被封存**的记录（口径 A）。
- （`§2.3-2`）封存理由（`seal.note`）要分两层说清：**结构化读**（`loadAll`）返回的 `sealed` 对象里带着它
  （翻回那天时，后来才封存的那条另外带 `sealed.afterAsOf: true`）；**展示与导出都不写它**——展示型输出
  （`book` / 回顾 / 渲染文本）、CLI `read --as-of` 的视图、数据导出（`exportMemory`）都摘掉。
  理由里可能有她写下的原话，不许借展示露出去。
- （`§2.3-3`）`asOf` 缺省 = 现在。

> 1.0 说明：0.x 这里写的是"封存之后才写下的封存理由……任何读法都不外露"。上面那句是把两层写明白
> （结构化读给、展示与导出不给）——**实现一个字节没动**，给宿主的行为一条没变，变化记录里单列了一条。

## 三、API 契约（六个动作）

以 `packages/core/lib/self-experience.js` 为准；其它模块（`unsaid` / `book` / `archive` / `recap`）各有独立契约，本文只覆盖经历这一条主线。

### 3.1 写入 `addExperience(dir, input) → row`

- （`§3.1-1`）**返回**：写入的完整记录（含生成的 `id`）。写进去什么，返回的就是什么——不是摘要、不是 id。
- （`§3.1-2`）**失败**：**抛异常**，不返回半成品。空 `text`、超长字段、`feeling` 超过 8 项都抛。
- （`§3.1-3`）**幂等性**：**不幂等**。每次调用都是一条新记录；宿主若要去重，自己按内容判断。
- （`§3.1-4`）写入是"追加 + 必要时补换行"，不重写文件：追加之前已经在文件里的字节，一个都不变。

### 3.2 读取 `loadAll(dir, { asOf }) → rows`

- （`§3.2-1`）**返回**：记录数组，按文件顺序。
- （`§3.2-2`）已封存的记录**仍然返回**，只是带上 sealed 对象——**过滤是调用方的事**（召回、书、醒来块各自必须过滤；备份与计数不过滤）。
- （`§3.2-3`）**坏行**：默认 **fail closed**（宁可报错，不把该藏的露出来）。`allowCorrupt` / `allowSealCorrupt` 是给备份/计数用的后门，**宿主不得用它做展示**。
- （`§3.2-4`）**后端**（阶段 1 起，可选）：`backend: 'file'`（默认，不传就是它）或 `'sqlite'`。同一份数据上两者结果逐条相等；`recall` / `currentView` 同样接受这个参数。sqlite 拿不到、目录没迁移、迁移后 JSONL 又变过，都**抛错**，不静默退回 file，也不当成空。

### 3.3 召回 `recall(dir, query, opts) → hits`

- （`§3.3-1`）**返回**：命中记录（含 `id`），可按 `limit` 截断。
- （`§3.3-2`）**可重复性**：同一份数据、同一个查询、同一组参数 → 同样的结果顺序。排序不稳定视为 bug。

### 3.4 封存 `setSealed(dir, { id, sealed, note }) → { ok, ... }`

- （`§3.4-1`）**成功**：`{ ok: true, id, sealed, at, noop }`。
- （`§3.4-2`）重复封存是 `noop: true`，**不报错**。
- （`§3.4-3`）**失败**：`{ ok: false, error }`，**不抛异常**（唯一例外是磁盘错误）。
- （`§3.4-4`）封存**不删除**任何东西。

### 3.5 改主意 `reviseExperience(dir, input) → 事件`

- （`§3.5-1`）只追加一条 `later` 事件；`then` 一个字都不动。
- （`§3.5-2`）目标 id 不存在时**明确报错**（返回 `{ ok: false, error }`，消息里说找不到），不留"谁也看不见的后记"。

### 3.6 导出 `book(dir, {...})` / `archive(dir, ...)` / `exportMemory(dir, {...})`

- （`§3.6-1`）导出是**只读**的；不得因为导出而修改任何数据文件。
- （`§3.6-2`）**展示型**导出（`book` / 回顾）必须尊重封存：默认不把封存正文写进导出物。
- （`§3.6-3`）**数据导出 `exportMemory` 是整份数据口径**（v1.1 起）：封存内容默认也导出，只打 `sealed: true` 标记、不带封存理由；`includeSealed: false` 时完全排除。展示型导出（`book` / 回顾）仍按上一条默认不写封存正文。见[擦除与审计](erase-audit-zh.md)。

## 四、错误契约

| 场景 | 形状 | 条款 |
| --- | --- | --- |
| 写入参数非法 | **抛错**（`Error`，消息里带字段名与上限） | §4-1 |
| 封存 / 解封目标不存在 | **返回** `{ ok: false, error }` | §4-2 |
| 读不出来（坏行、权限） | **抛错**，绝不返回空数组冒充"没有" | §4-3 |
| 并发写 | v1 **不承诺**并发安全；单写者假设见第六节 | §4-4〔非承诺〕 |

## 五、兼容承诺（v1 内）

1. **只加不减**（`§5-1`〔流程〕）：新增字段、新增可选参数、新增事件类型都算兼容；
2. **不改语义**（`§5-2`）：`then` 不可变、as-of 口径、封存≠删除——三条任何版本都不改；
3. **破坏性变更走 v2**（`§5-3`〔流程〕）：v2 与 v1 **双读一个 minor 周期**，迁移工具随 v2 发布；
4. **弃用**（`§5-4`〔流程〕）：先文档标注一个 minor，再在下一个 minor 移除；
5. **id 永不复用**（`§5-5`）：包括迁移时。

> §5-1 / §5-3 / §5-4 标〔流程〕：它们管的是"我们以后怎么改动"，不是某一次调用的可观测行为，
> 没法写成运行时断言。它们的落地检查在 CHANGELOG 与发布评审里，不在测试里。

## 六、明确不承诺（v1）

- （`§6-1`〔非承诺〕）**单条物理删除自 v1.1 起提供**（`erase`，见[擦除与审计](erase-audit-zh.md)）；**备份 / 快照里的历史副本不追溯**。整库删除仍是 `purge`。
- （`§6-2`〔非承诺〕）**不承诺多写者**：同一目录多进程并发写会导致丢行；需要并发请在外层串行化。
- （`§6-3`〔非承诺〕）**不承诺明文存储之外的加密**：数据是明文 JSONL，磁盘加密由宿主负责。
- （`§6-4`〔非承诺〕）**不承诺可用性 / SLA**：这是库，不是服务。
- （`§6-5`〔非承诺〕）**不承诺向量检索**：v1 是字面 + 结构检索；语义检索在路线里（阶段 2）。

## 七、给宿主的责任边界

（`§7-1`〔非承诺〕）下表是**约定**，不是可断言行为：它说的是"出了问题该找谁"，不是"库会做什么"。
完整版（含"不许宿主做的四件事"与出事后的算账）见 [`host-boundary-zh.md`](host-boundary-zh.md)。

| 宿主要负责 | 库负责 |
| --- | --- |
| 鉴权、限流、会话 | 记录的不可变与追加 |
| 什么时候写、写什么 | 写入的校验与上限 |
| 提示词怎么拼、注入多少 | 召回结果与封存过滤 |
| 备份调度、磁盘加密 | 数据自洽（坏行要报错） |
