# v1 契约（数据 + API + 兼容承诺）

> 这一份是**契约**，不是文档。它写的是：宿主能依赖什么、库承诺不做什么、破坏性变更怎么走。
> 状态：1.0 之前冻结；在此之后只做加法（见第五节）。
> 配套：[`schemas/record.v1.json`](../schemas/record.v1.json)、契约测试 `tests/contract-v1.test.mjs`。

## 一、根原则

1. **记录不可变。** 一条经历写进去之后，那一行永远不改。改主意、封存、想起次数、没弄完后来怎么样了——全部是**独立事件**，追加到各自的事件文件。
2. **一条记录可以被整条撤回（`erase`）。** 撤回后，正文与关联事件一并删除，只保留墓碑：id、撤回时间、原因、删除前内容的哈希。
3. **墓碑不含正文，也不可用于恢复。** 它只说明"这条存在过、被撤回了"。
4. **封存不是删除。** 封存只是"别再主动提起"；数据还在，可以解封。删除是另一件事——单条走 `erase`，整库走 `purge`（见第六节与[擦除与审计](erase-audit-zh.md)）。

## 二、数据契约

### 2.1 文件布局

```
<memory-dir>/
  self-experience.jsonl        经历，一行一条，只追加
  later-events.jsonl           改主意 / 回头想
  seal-events.jsonl            封存 / 解封
  recall-events.jsonl          想起次数
  unfinished-events.jsonl      没弄完的事后来怎么样了
  unsaid.jsonl                 没说出口的抽屉（独立空间，永不自动注入）
  tombstones.jsonl             撤回墓碑（v1.1 起；{v, id, ids, at, reason, actor, hash}，不含正文）
  audit.jsonl                  审计（v1.1 起；{at, actor, action, ids, note}，只记 id 与动作）
  fact-events.jsonl            事实键事件（v1.2 起、可选；只在调用 factKey.setFact 时出现）
```

所有文件都是 JSONL（一行一个 JSON）。解析方必须容忍**最后一行没有换行**，以及**坏行**——坏行要报出来，不能当空。

可选（阶段 1 起）：`memory.sqlite`——同一份数据换一个容器（见 [存储后端](storage-backend-zh.md)）。记录与事件的 JSON 形状和上面的 JSONL 逐条相同；迁移是叠加，JSONL 不删、不改。

### 2.2 记录（`self-experience.jsonl`）

字段定义以 [`schemas/record.v1.json`](../schemas/record.v1.json) 为准。要点：

| 字段 | 契约 |
| --- | --- |
| `id` | `exp_` 前缀，**不透明**。宿主不许解析、不许按格式拼 id、不许复用。 |
| `at` / `day` | `at` 是写入时刻（ISO 8601），`day` 是本地日。按"那一天"检索只看 `day`。 |
| `then.*` | 写入那一刻的原样：`text` 必填（≤2000），其余可选。**任何系统都不许替她改写 `then`。** |
| `later` | 写入时恒为空数组。后续变化只进事件文件，**不回写**。 |
| `sealed` | **不是记录字段**。封存状态由 `seal-events.jsonl` 推出；记录本身不含它。 |

### 2.3 时间语义（as-of）

- `read({ asOf })` 返回**那一刻已经存在、且当时还没被封存**的记录（口径 A）。
- 封存之后才写下的封存理由（`seal.note`）属于"未来信息"，任何读法都**不外露**。
- `asOf` 缺省 = 现在。

## 三、API 契约（六个动作）

以 `packages/core/lib/self-experience.js` 为准；其它模块（`unsaid` / `book` / `archive` / `recap`）各有独立契约，本文只覆盖经历这一条主线。

### 3.1 写入 `addExperience(dir, input) → row`

- **返回**：写入的完整记录（含生成的 `id`）。
- **失败**：**抛异常**，不返回半成品。空 `text`、超长字段、`feeling` 超过 8 项都抛。
- **幂等性**：**不幂等**。每次调用都是一条新记录；宿主若要去重，自己按内容判断。
- 写入是"追加 + 必要时补换行"，不重写文件。

### 3.2 读取 `loadAll(dir, { asOf }) → rows`

- **返回**：记录数组，按文件顺序。已封存的记录**仍然返回**，只是带上 sealed 对象——**过滤是调用方的事**（召回、书、醒来块各自必须过滤；备份与计数不过滤）。
- **坏行**：默认 **fail closed**（宁可报错，不把该藏的露出来）。`allowCorrupt` / `allowSealCorrupt` 是给备份/计数用的后门，宿主不得用它做展示。
- **后端**（阶段 1 起，可选）：`backend: 'file'`（默认，不传就是它）或 `'sqlite'`。同一份数据上两者结果逐条相等；`recall` / `currentView` 同样接受这个参数。sqlite 拿不到、目录没迁移、迁移后 JSONL 又变过，都**抛错**，不静默退回 file，也不当成空。

### 3.3 召回 `recall(dir, query, opts) → hits`

- **返回**：命中记录（含 `id`），可按 `limit` 截断。
- **可重复性**：同一份数据、同一个查询、同一组参数 → 同样的结果顺序。排序不稳定视为 bug。

### 3.4 封存 `setSealed(dir, { id, sealed, note }) → { ok, ... }`

- **成功**：`{ ok: true, id, sealed, at, noop }`；重复封存是 `noop: true`，**不报错**。
- **失败**：`{ ok: false, error }`，**不抛异常**（唯一例外是磁盘错误）。
- 封存**不删除**任何东西。

### 3.5 改主意 `reviseExperience(dir, input) → 事件`

- 只追加一条 `later` 事件；`then` 一个字都不动。
- 目标 id 不存在时**明确报错**，不留"谁也看不见的后记"。

### 3.6 导出 `book(dir, {...})` / `archive(dir, ...)`

- 导出是**只读**的；不得因为导出而修改任何数据文件。
- **展示型**导出（`book` / 回顾）必须尊重封存：默认不把封存正文写进导出物。
- **数据导出 `exportMemory` 是整份数据口径**（v1.1 起）：封存内容默认也导出，只打 `sealed: true` 标记、不带封存理由；`includeSealed: false` 时完全排除。展示型导出（`book` / 回顾）仍按上一条默认不写封存正文。见[擦除与审计](erase-audit-zh.md)。

## 四、错误契约

| 场景 | 形状 |
| --- | --- |
| 写入参数非法 | **抛错**（`Error`，消息里带字段名与上限） |
| 封存 / 解封目标不存在 | **返回** `{ ok: false, error }` |
| 读不出来（坏行、权限） | **抛错**，绝不返回空数组冒充"没有" |
| 并发写 | v1 **不承诺**并发安全；单写者假设见第六节 |

## 五、兼容承诺（v1 内）

1. **只加不减**：新增字段、新增可选参数、新增事件类型都算兼容；
2. **不改语义**：`then` 不可变、as-of 口径、封存≠删除——三条任何版本都不改；
3. **破坏性变更走 v2**：v2 与 v1 **双读一个 minor 周期**，迁移工具随 v2 发布；
4. **弃用**：先文档标注一个 minor，再在下一个 minor 移除；
5. **id 永不复用**：包括迁移时。

## 六、明确不承诺（v1）

- **单条物理删除自 v1.1 起提供**（`erase`，见[擦除与审计](erase-audit-zh.md)）；**备份 / 快照里的历史副本不追溯**。整库删除仍是 `purge`。
- **不承诺多写者**：同一目录多进程并发写会导致丢行；需要并发请在外层串行化。
- **不承诺明文存储之外的加密**：数据是明文 JSONL，磁盘加密由宿主负责。
- **不承诺可用性 / SLA**：这是库，不是服务。
- **不承诺向量检索**：v1 是字面 + 结构检索；语义检索在路线里（阶段 2）。

## 七、给宿主的责任边界

| 宿主要负责 | 库负责 |
| --- | --- |
| 鉴权、限流、会话 | 记录的不可变与追加 |
| 什么时候写、写什么 | 写入的校验与上限 |
| 提示词怎么拼、注入多少 | 召回结果与封存过滤 |
| 备份调度、磁盘加密 | 数据自洽（坏行要报错） |
