## 关于"借鉴"的边界

- 只借鉴**思路与接口设计**，实现一律自写，并跑本项目的契约测试与评测闸门；
- 每个落点都在 `CHANGELOG` 里写明来源与许可证；
- 如果将来要直接复制 MIT 项目的代码片段，会在对应文件的头部注明来源与版权声明。

## 阶段 5（2026-11-27，1.0）：这一段没有新的借鉴落点

S11 做的事（契约升 1.0 + 稳定面、条款编号与覆盖矩阵、类型面、迁移演练、Python 封装、宿主责任边界）
**没有引入任何第三方代码或设计**，所以这里没有新增条目。写清楚是为了不让"致谢"变成一张只增不减的名单：

- **条款编号 + 覆盖矩阵**（`docs/contract-v1-zh.md` 附录 A、`tests/contract-coverage.test.mjs`）：
  自己是自己想出来的做法——先把条款编号化，再用测试强制"文档里说的每一条都得有用例名带着"。
  这个思路和 xiaoyu-wake 的 `DISCIPLINE.md` 里"可数 / 半可数 / 不可数"三档**在气质上接近**
  （都是"先承认哪些管得到、哪些管不到"），但那里的三档写的是**人**该怎么自省，这里写的是
  **CI** 该怎么拦住"写了没验"——载体与判据都不同，不算借鉴落点，记在这里只是把相似之处说明白。
- **迁移演练**（`tools/migrate-drill.mjs`）：可重复演练 + 反向用例（坏行/覆盖/过期）是迁移工具本身的
  工程常识，没有参照具体项目。已致谢的 Lysmor"灾后复活（整包备份 + 换机恢复）"在 0.26.3 的
  `archive.importArchive` 上落过地，这一段没有新的东西从它那里来。
- **Python 封装**（`adapters/python/`）：只是 `adapters/cli/memory-cli.mjs` 的子进程包装，
  没有参照任何现成的 Python 客户端。
