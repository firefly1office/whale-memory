# 事故复盘：测试把真实记忆目录删了

- 日期：2026-11-22
- 影响：一台开发机上，某插件的真实数据目录被测试进程递归删除
- 数据：已从当天早些时候的备份恢复；事故之后到恢复之间的新写入无法找回
- 代码：已修复并加了护栏；本文件公开，是因为"坏了怎么修"比"我们多厉害"更值得被看到

## 发生了什么

一次例行验证跑的是"入口文件 + 全套测试"。入口文件当时有语法错误，测试套件里有一条用例：

1. 先从运行环境（`DATA_DIR` / 用户级环境变量）**推算出清理目标**；
2. 之后才设置自己的临时数据目录；
3. 入口加载失败 → 用例抛错；
4. 但 `finally` 照样执行，对第 1 步算出来的路径做了 `rmSync(..., { recursive: true })`。

结果：真实数据目录整棵被删，连"哪些被遗忘"的标记文件一起没了。

## 为什么没被挡住

- 删除用的是从环境继承来的路径，不是自己造的临时目录；
- 其它用例都用 `mkdtemp`，这一条是例外，且看起来"合理"（注释还写着"按它实际用的目录来验"）；
- 入口语法错误只让用例抛错，不会阻止 `finally`；
- 当时的备份只覆盖了一部分数据，迁移备份里恰好不含这些文件。

## 修了什么

1. **删掉病灶**：该用例只用自己 `mkdtemp` 的目录，不再从环境推导任何路径。
2. **加护栏**：仓库测试里所有递归删除都走 `safeRemove()`（`tests/_safety.mjs`），目标必须位于系统临时目录下，否则抛 `TEST_UNSAFE_REMOVE`；连"临时目录本身"也拒绝。
3. **护栏自测**：`tests/safety-guard.test.mjs` 故意去删真实路径，必须在删除前失败，且文件原样还在。
4. **恢复要按文件逐个比**：目录存在不等于目录完整。第一次恢复只补了缺失的顶层条目，漏掉了一个"存在但为空"的子目录。

## 教训（可复用）

- 测试里的删除目标只能来自 `mkdtemp`，不许从环境变量、配置模块、相对路径推导。
- 校验"我删的是临时目录"这件事，要写成代码，不要写成注释。
- 入口语法错误时不要跑全套测试；先 `node --check`。
- 恢复数据时按文件清单比对，不要只比顶层目录。
- 事故之后先冻结，再修；不要在同一个夜里既修代码又改数据。

## 复现与验证

```bash
npm test                 # 包含护栏自测
node --check <entry>     # 跑全套之前先做
```

护栏自测会尝试删除一个真实路径，期望它**在删除之前**抛错。
