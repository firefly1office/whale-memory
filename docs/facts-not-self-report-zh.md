# 只记事实，不记自述

> 这篇讲一个很小的区分，但它决定了整套记忆可不可信：**“她做了什么”是事实，“她说她做了什么”是自述。**
> 两者都可以存，但不能混成同一种东西。

## 一句话

**事实要能核对；自述只能当声明。**

## 为什么不能把自述当事实

模型很擅长把话说圆：

- 她可以说“我今天读了书”，但书签可能没动；
- 她可以说“我自己想写的”，但触发可能来自一句用户指令；
- 她可以说“我记得那件事”，但记录里可能只有一句感想；
- 她可以说“我没有改过”，但文件哈希已经变了。

这些话不是撒谎，是模型在生成“听起来合理”的叙述。把它们直接写进“事实”栏，后面所有统计、召回、关系判断都会跟着偏。

## 两类东西

| | 事实 | 自述 |
| --- | --- | --- |
| 例子 | 工具调用、文件字节、时间戳、书签位置、退出码、哈希 | “我读了”“我想写”“我记得”“我自己发起的” |
| 来源 | 宿主的执行路径、磁盘、日志 | 模型生成的自然语言 |
| 能证明什么 | 发生过什么、什么时候、结果如何 | 她怎么描述这件事 |
| 不能证明什么 | 她为什么做、她当时怎么想 | 事情真的发生过 |

## 落到代码里的四条

### 1. `then` 是自传，不是审计日志

`then` 是她当时写下的经历，值得原样保留；但它不等于“外部事件已发生”。一条 `then` 可以证明“她那天写下了这句话”，不能单独证明“她那天真的去了海边”。

外部事实要另外有来源：文件、工具结果、时间戳、引用。不要把 `then` 当证据去反推现实。

### 2. 自主动作只看可核对的动作

`self-actions` 只记：

```json
{"v":1,"at":1795433813075,"day":"2026-11-23","action":"draft_save","source":"asked","outcome":"ok","itemRef":"it_..."}
```

- `action`：做了什么，来自工具名/动作白名单；
- `source`：谁发起的，由调用方声明，不由模型自述；
- `outcome`：结果，来自执行结果；
- `triggerHash` / `triggerLen`：只留长度和指纹，不存触发原文（短句的裸哈希等于明文）。

`self` 只在“确认没有外部触发”时出现；判不出就记 `unknown`。宁可少记一次“自主”，也不要把“被叫去做”写成“她自己想做”。

### 3. 时间线只记文件事实

`own-time` 记录的是“她的东西有没有变”：稿本版本、书签、事项状态。它不写“她今天很努力”，只写“书签从第 13 段到了第 28 段”。

叙事可以后写，事实必须先有。

### 4. 声明和事实分开对账

`own-claims` 存“她说过什么”，`own-time`/`self-actions` 存“实际发生了什么”。两边分开，才能回答：

- 她说写了，稿本有没有新版本？
- 她说读了，书签有没有动？
- 她说自己发起的，`source` 是什么？

对不上时，不要替她圆。写“她说了 X；记录里没有 Y”，比写“她做了 Y”诚实。

## 宿主接入时最容易犯的错

1. **把模型输出直接当事件写进经历。** 模型说“我今天去了图书馆”，宿主就写一条 `then`；这会把叙述变成“事实”。
2. **用自述统计自主性。** “她说了三次自己想做”不等于自主，去看 `self-actions` 的 `source`。
3. **读不出来就当空。** 文件权限/坏盘导致的空，不是“没有记录”；要 fail-closed，报错，不要让她说“我不记得”。
4. **把短文本的哈希当匿名。** 短句可以被字典枚举；要留痕就用带密钥的 HMAC，或只存长度。
5. **为了让报表好看，把 `unknown` 改成 `self`。** 这是最贵的一种错：它会把“无法判断”卖成“主动性”。

## 这套做法的代价

- 会经常出现 `unknown`，报表不好看；
- 需要宿主真的记录执行结果，不能只靠模型写总结；
- 需要区分“读不到”和“没有”，代码更啰嗦；
- 不能拿“她说过”当证据，很多叙事要降级成“她说”。

换来的东西是：每一条“她做过”都能被核对；每一条“她记得”都能追到原文；没有记录时，她可以真的说“不记得”。

## 边界

这套区分不是安全边界。本地文件可以被手工改，宿主可以被替换，模型可以编得更像。它只保证一件事：

**在这个仓库的代码路径里，事实和自述不会因为一句“她说”就被混在一起。**

要更强的保证，需要外部审计、签名日志或可信执行环境；那是另一个问题。
