# 计划与后果：让她自己定的时间真的算数（设计记录）

> 记录一个很小的闭环：角色给自己定一个时间 → 到点被提醒 → 做过/没做过 → 醒来时看到后果。所有数字来自合成时钟与隔离副本，不含真实对话原文。

## 为什么要做

角色能说"我今晚想看书"，但这句话说完就散了：

- 没有登记，就没有"到点"；
- 没有证据，就无法知道她到底做没做；
- 没有回看，"说过的话"就没有后果。

## 状态机

```
active ──到点被注入──> shown ──窗口内做了目标页──> done
   │                     │
   │                     └──窗口结束没做──> missed
   └──窗口结束从未注入──> expired
任何状态 ──她改时间──> rescheduled
```

关键约束：

- **shown 最多一次**，且必须真的注入到本轮 prompt；
- **done 只认真实翻页记录**（哪一页、成功返回），不靠模型自述；
- 第一轮已经超过窗口的，不追溯补记；
- 回看只陈述记录事实，禁止"应该/请/记得/未完成"这类词；
- 目标页写不清的计划，回看保持中性，不做结论。

## 回看的措辞

```
【计划回看 · <登记时间> 你定过：『<原文>』｜窗口到 <时间>】
记录：窗口内打开了第 N 页。
记录：窗口内没有打开第 N 页。
记录：窗口内没有这条计划的注入记录。
记录：你把它改到了新的时间。
记录：这条计划没有可核验的目标页，不做结论。
```

## 可见性提示

上线后她一直没有自己登记过计划。加了一次中性提示：

```
（你有一个工具：`self_plan`——可以给自己定一个时间。它是工具，不是要求。）
```

最多三天、每天一次；当天已有计划/回看注入就不占位；只出现，不催办。

## 验收

- 状态机单测：expired / missed / done / rescheduled 分支，证据只认真实翻页，窗口外不算；
- 接线测试：真的跑 `before-context` + `after-llm`，看原文是否进最终消息、是否只出现一次；
- 回看只出现一次；注入成功才标记，失败下次重试；
- 泄露/越界：不同人设不串计划；群聊不注入。

## 教训

- **"她自己定的"和"系统安排的"是两件事**：提示只说明工具有没有，不替她决定做什么；
- **后果要可核验**：能核验的行为（翻到第几页）才有回看，核验不了的保持中性；
- **措辞即态度**：回看写"记录显示…"而不是"你没做到"，角色才不会把回看当成指责。
