# 外发预检：正文干净不等于没泄漏（设计记录）

> 一句话：**你写的材料可以过审，带着材料的那个进程可能不过审。**

## 为什么要有这一层

一次真实的红线事故里，外发材料的正文是干净的——没有路径、没有账号、没有原文。
泄漏发生在调用链：命令行工具在它自己的系统提示里带上了本机主目录，而本机用户名恰好
能和账号对上。我们的闸门只扫了正文，所以什么都没拦到。

结论不是"再写一条更长的正则"，是：**外发要分两层看。**

| 层 | 谁控制 | 能不能查 |
| --- | --- | --- |
| 材料正文（你要发的那段字） | 我们 | 能，逐字扫 |
| 调用链（CLI 自带提示、环境变量、SDK 隐式字段） | 不归我们 | **查不到**，只能换通道或换做法 |

`tools/preflight.mjs` 只做第一层，并且在输出里明确告诉你第二层管不到。

## 扫什么

| 规则 | 例子 | 为什么 |
| --- | --- | --- |
| 本机主目录 | `/home/<user>/…`、`C:\Users\<user>\…` | 用户名经常就是账号的一部分 |
| Windows / POSIX 绝对路径 | `D:\…`、`/Users/…` | 路径会带目录结构与用户名 |
| 6–11 位连续数字 | `13800001234` | 像手机号、QQ 号；**8 位日期（`20261125`）不算** |
| 16 位以上连续十六进制 | `abcdefabcdefabcdef` | 像密钥、令牌、长哈希 |
| 私钥头 | `-----BEGIN … PRIVATE KEY-----` | 一眼可见，但常被复制进样例 |

规则故意写死、不做可配置：能配的规则最后都会为了"这次先过"被调松。
要放宽就先改规则文件，并把它当成一次代码改动来过审。

## 怎么用

```bash
node tools/preflight.mjs 材料.md 证据.json      # 命中即退出码 1
node tools/preflight.mjs --text "一段话"         # 临时检查
```

放进流程里的位置：**任何外发之前**（问外部模型、贴工单、发邮件、截图）跑一次；
纸面上"应该没问题"的材料也要跑——这次事故的正文当时就是"应该没问题"。

## 它做不到的四件事

1. **管不到调用链**：CLI 的系统提示、默认参数、遥测、代理设置，都不在这个脚本的视野里。
   能做的是换一个可审计的通道，或者在材料里不出现任何需要这些字段的东西。
2. **管不到语义泄漏**：改写过的人名、拆开的编号、代称，它认不出来。语义风险靠人审。
3. **管不到二进制**：图片 EXIF、PDF 元数据、Office 作者字段——要先清元数据再发。
4. **不放宽就等于不拦**：`--allow-raw` 这类开关一旦存在，迟早会被当成默认。这里没有。

## 测试

`tests/preflight.test.mjs`（6 项）：干净文本不误报、日期不误判、长短数字边界、
路径与私钥头、长十六进制、命令行退出码。规则改动必须先改这里的用例。
