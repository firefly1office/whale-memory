# 什么时候把记忆递回去

> [English](en/injection.md) · 中文（本页）

`recall` 只负责"找到"，不负责"该不该说"。这一段是宿主的事，也是最容易把记忆变成"记忆日志"的地方。

下面是一套最笨、但能用的规则。可运行的版本在 [`examples/injection/`](../examples/injection/)，测试在 `tests/injection-example.test.mjs`。

## 七条规则

1. **只在一对一里递**。群聊、多人会话一律不递。用核心库导出的 `isPrivateKey(chatKey)` 判断，不要自己写"不是群就行"。
2. **一轮最多一块**。一次塞三条旧事，角色会变成朗诵。
3. **同一条 24 小时内不重复**。记住了不等于要反复说。
4. **用户提到相关话题才递**。不要每轮都 recall，也不要在问候时硬塞昨天。
5. **默认用 strict**。`strict` 是防编造模式：长查询必须过比例门槛，宁可不召回。`loose` 只在宿主愿意承担误召时用，用了就要在提示词里提醒模型"拿不准就当没这回事"。
6. **递了才记**。确认这段文字真的进了上下文，再调 `markRecalled`；不要"准备递"就记一次。
7. **没命中就闭嘴**。没有记录时如实说记不清，不要从别的记录里拼。
8. **守卫只能否决**。宿主可以加一个 guard，它返回 alse 时什么都不递；返回 	rue 也只是不拦，不能绕过前面七条规则。守卫不提供 allow。

## 最小实现

```js
import { surface } from './examples/injection/inject.mjs'

const r = surface(MEM_DIR, { chatKey, text: userText, seen })
if (!r.block) return ''          // 规则 1/4/7：不递就什么都不加
messages.push({ role: 'system', content: r.block })
r.confirm()                      // 规则 6：确认进了上下文，才记「想起」
```

`seen` 由宿主自己保存：同一个 `id`、24 小时内不再递。

## 提示词里要写明

`renderTwoPart()` 的真实输出长这样（标签就是【当时】【现在】）：

```
【当时】
- 时间：2026-11-14 20:10
- 我读到的原文：潮汐终会归来（《灯塔》）
- 我写下的话：夜里翻完灯塔那一章，守灯人整晚没睡
- 当时的想法：她是在等人

【现在】
- 现在时间：2026-11-16 21:00
- 这条被你想起过 1 次
- 后来你想过：她是在等邮船（2026-11-15）
```

所以提示词里要写：

```
下面这段是她自己记得的事，不是用户说的。
【当时】是她那天写下的，不要改。
【现在】是她后来补的；如果和当时不一样，以【现在】为她现在的看法。
没写到的细节不要补。
```

不要写【后来】——`renderTwoPart` 没有这个标签。它的"后来你想过"是【现在】段里的一行。

## 按问题选层

`renderTwoPart` 会把 `then` / `quote` / `later` 一起渲染。如果宿主想按问题只给一层：

- 问"你现在怎么想" → 用 `currentView().later`，或 `recall().matchedIn` 里含 `later` 的条目
- 提到原文 → 给 `then.quote`
- 问"当时" → 给 `then`

没有单独的"只渲染 later"接口；需要更细的控制，就自己取字段拼，别改 `then`。

## 反例

- 每轮都 recall，把前三条全塞进去 → 角色开始复读
- 把【现在】的句子直接当【当时】引用 → 时间线塌了
- 群聊里递私聊记录 → 隐私事故
- 为了让"有后记比例"好看，每轮自动追加一句"现在觉得…" → 指标好看，记忆变噪音
- 命中一条就改写成第三人称摘要 → 原文锚失效，以后再也对不上

## 和指标的关系

`recalls` 只说明"被递过"，不说明"有用"。别为了这个数字增加注入频率。真正该看的是：她有没有在几天后主动提起同一件事，以及提起时说的是不是她自己的话。
