# 什么时候把记忆递回去

`recall` 只负责"找到"，不负责"该不该说"。这一段是宿主的事，也是最容易把记忆变成"记忆日志"的地方。

下面是一套最笨、但能用的规则。先用它，再按你的角色调整。

## 七条规则

1. **只在一对一里递**。群聊、多人会话一律不递；用会话键白名单，不要写"只要不是群就行"。
2. **一轮最多一块**。一次塞三条旧事，角色会变成朗诵。
3. **同一条 24 小时内不重复**。记住了不等于要反复说。
4. **用户提到相关话题才递**。不要每轮都 recall，也不要在问候时硬塞昨天。
5. **分清楚在说哪一层**：用户问"你现在怎么想"→ 给 `later`；用户提到原文 → 给 `quote`；用户问"当时"→ 给 `then`。`renderTwoPart` 会一起给，但你要在提示词里说明这是哪一层。
6. **递了才记**。确认真的进了上下文，再调 `markRecalled`；不要"准备递"就记一次。
7. **没命中就闭嘴**。没有记录时如实说记不清，不要从别的记录里拼。

## 一个最小实现

```js
const hits = recall(MEM_DIR, userText, { limit: 1, mode: 'loose' })
const hit = hits[0]

const canShow =
  isPrivateChat(chatKey) &&                       // 规则 1
  hit &&                                          // 规则 4/7
  hit.id !== lastShownId &&                       // 规则 3（进程内也要记）
  now - (lastShownAt[hit.id] || 0) > 24 * 3600e3  // 规则 3
if (!canShow) return ''

const block = renderTwoPart(hit)                  // 规则 5
markRecalled(MEM_DIR, hit.id)                     // 规则 6：确认进上下文后再记
lastShownId = hit.id
lastShownAt[hit.id] = now
return block
```

`lastShownAt` 存在哪由宿主决定：进程内存、`self-settings.json` 旁边的小文件都行。别写进经历文件。

## 提示词里要写明

```
下面这段是她自己记得的事，不是用户说的。
【当时】是她那天写下的，不要改。
【后来】是她后来补的，如果和当时不一样，以"后来"为她现在的看法。
没写到的细节不要补。
```

不写这三句，模型很容易把 `later` 当成"当时就知道"，或者把 `then` 改写成更通顺的版本。

## 反例

- 每轮都 recall，把前三条全塞进去 → 角色开始复读
- 把 `later` 的句子直接当 `then` 引用 → 她"当时"就知道后来的事，时间线塌了
- 群聊里递私聊记录 → 隐私事故
- 为了让"改主意率"好看，每轮自动追加一句"现在觉得…" → 指标好看，记忆变噪音
- 命中一条就改写成第三人称摘要 → 原文锚失效，以后再也对不上

## 和指标的关系

`recalls` 只说明"被递过"，不说明"有用"。别为了这个数字增加注入频率。真正该看的是：她有没有在几天后主动提起同一件事，以及提起时说的是不是她自己的话。
