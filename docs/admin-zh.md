# 管理页（只读，admin）

> 借自 ru-гу 的管理页与 Lysmor 的星图（只学「一眼看清库里有什么」的做法；后者是 AGPL，只学设计）。
> 星图不在这一页重复做（S2 在做）。这一页只回答数字与流水账。
> 代码：`tools/admin.mjs`；测试：`tests/admin.test.mjs`（9 条）。

## 两种模式

```bash
# 1) 导出静态 HTML：自包含，双击就能看，不联网
node tools/admin.mjs <memory-dir> --export <out.html> [--limit=N]

# 2) 起本地只读页（只绑 127.0.0.1；默认随机端口，会把地址打出来）
node tools/admin.mjs <memory-dir> --serve [--port=N] [--limit=N]

# 3) 什么都不给：只打印上面这份用法，一个端口都不开
node tools/admin.mjs
```

- **默认不自动启动**：不带 `--serve` 就不会监听任何端口；只给目录、不给模式也一样只打印用法。
  没有 cron、没有宿主钩子、没有 npm script 会跑它。
- `--limit=N`：每个列表最多显示几条（1..200，默认 20）。
- `--port=N`：只对 `--serve` 有效；默认 `0`（随机端口），打印出来的地址是真实端口。
- 退出码：`0` 正常；`1` 数据读不出来 / 有坏行；`2` 用法错。

## 四组数字的口径

| 数字 | 口径 | 来源 |
| --- | --- | --- |
| 经历（总 / 未封存 / 已封存） | **`loadAll` 能读出来的经历条数**。没有正文的旧行不算（与书 / 召回同口径）；封存状态由封存事件推出 | `self-experience.loadAll` |
| 撤回（墓碑条数） | `tombstones.jsonl` 的行数。一条经历只留一块墓碑 | `tombstones.readAll` |
| 审计 | `audit.jsonl` 的行数；另给其中 `action: 'erase'` 的条数 | `audit.read` |
| 召回事件 | `recall-events.jsonl` 的行数 | `recallEvents.readAll` |

页面里的数字带 `data-stat` 属性（`records-total` / `records-unsealed` / `records-sealed` /
`tombstones-total` / `audit-total` / `audit-erase` / `recalls-total`），测试逐项与库读出来的值对拍，
不是自己另算一遍。

列表（最近 `--limit` 条，新的在前）：

- **经历**：只列 id / 日子 / 种类 / 封存状态，**正文一个字都不渲染**。
- **墓碑**：id / 时间 / 原因 / actor。
- **审计**：时间 / actor / 动作 / ids / note。
- **最近召回**：时间 / 经历 id。**不列查询原文**——和审计同一个理由：查询里经常带着她写的原话。

## 隐私边界

1. **封存正文不出现**：封存的经历只给 id / 日子 / 种类和「已封存」标记。测试里塞了一段哨兵正文，
   对导出的 HTML 按字节搜不到。
2. **抽屉不读**：`tools/admin.mjs` 根本不 import `unsaid`，抽屉正文不可能漏进页面。测试同样用哨兵验证。
3. **查询原文不抄**：召回列表只有 id 与时间。
4. **动态文本一律转义**：id、撤回原因、审计 note、actor 都过 `esc()`，不拼进标签/属性/脚本。
5. **静态导出没有可用的删除入口**：没有 `method="post"` 表单、没有外链脚本/样式、没有 `http(s)://` 地址；
   页面上有一段「撤回一条」的说明，但按钮不可用（要撤回请用 `--serve` 或直接调库）。

## 「撤回一条」为什么必须有二次确认

撤回是**破坏性且不可恢复**的操作：记录、挂在它身上的后记/想起/没弄完/联想事件都会被删掉，
只留一块墓碑与一条审计（`eraseExperience` 自己负责写，这一页不自己删文件）。

所以做了三层：

1. **页面**：表单 `onsubmit` 里 `confirm()` 一次（手滑点不到两次）。
2. **服务端**：表单体里必须带 `confirm: true`；缺了直接 400，**不碰库**。测试断言：没带 confirm 的请求
   记录仍在。
3. **令牌**：每次 `--serve` 启动随机生成一个 token，只有本次返回的页面表单里有。别的站点就算盲发一个
   带 `confirm=true` 的表单，也拿不到 token → 403。测试断言：有 confirm 没 token 也删不掉。

三条都过了才会调 `eraseExperience(dir, { id, reason, actor })`；成功之后墓碑多一条、审计多一条 erase。

## 只读边界

- 服务端只认两个读路径：`GET /`、`GET /health`；唯一的写路径是 `POST /erase`。
- 别的方法/路径：`/` 上的非 GET 回 405，`/erase` 上的非 POST 回 405，其它路径 404。
- 不提供静态文件服务，不读请求里的路径，不能借这个端口读磁盘上别的东西。
- 页面每次请求都重新读库（数据变了刷新就新）；**GET 不写任何文件**——测试里对整目录做 sha256
  前后比对，GET 一遍后逐文件相同。
- 只绑 `127.0.0.1`（不传 host 通配），局域网其它机器连不上。

## 坏行 fail closed

- 经历文件有坏行：`loadAll` 抛错 → `--export` 退出 1，**不生成也不改写导出文件**（测试先放一个
  已存在的输出文件，确认失败后原样还在）；`--serve` 的 `GET /` 回 500 错误页，不渲染「少了几条」的页面。
- 墓碑 / 审计 / 召回事件有坏行：同样整页拒绝（墓碑、召回自己数坏行；审计由 `audit.read` 抛）。
- 页面请求失败时不会缓存，也不会把错误吞成空表。

## 默认关怎么证明

1. **不起端口**：不带参数、或只给目录不给模式时，进程打印用法后立刻退出（测试用 `spawnSync` 断言退出码 0、
   输出里有 `--export` / `--serve`、没有 `http://127.0.0.1:端口`；如果它真起了服务，进程会挂着，测试会超时）。
2. **没有自动跑**：没有 cron、没有宿主钩子、没有 npm script、没有 import 这个工具的任何模块
   （全仓 `admin.mjs` 只出现在工具本身、测试和本文档里）。
3. **导出物不带能力**：静态 HTML 里没有可提交的表单、没有外链、没有 `http(s)://` 地址（测试按字节断言）。
4. **读路径只读**：`GET /` 前后整目录 sha256 不变（测试断言）。
5. **既有行为不变**：本段只新增 3 个文件（工具、测试、本文档），没有改 `packages/core` 下任何文件。

## 明确的限度（没验什么）

- **没有鉴权**：只绑本机 + confirm + 每次启动的随机 token，这是防手滑与防跨站盲打，不是登录系统。
  同一台机器上的其它进程想加害，可以绕过页面直接调库——那不在这一层的承诺里。
- **没有在真实浏览器里看过**：环境里没有 jsdom / 浏览器，验证是用正则查 HTML 结构 + 自包含断言；
  没有真点过按钮，也没有截图。
- **端口**：没验端口被占用时的行为（会走 `server.on('error')` 退出 1，但没写用例）；没验 Windows
  防火墙/杀软对 127.0.0.1 监听的影响。
- **规模**：没在大库上跑过（`loadAll` 会整库读进内存；页面每次请求都重读）。十万条规模下的耗时与内存没测。
- **SQLite 后端**：这一页走 `loadAll` 默认的 file 后端；没验 `memory.sqlite` 存在时的展示口径。
- **导出物里会有人的话**：墓碑的 `reason`、审计的 `note` 是自由文本，会原样出现在 HTML 里
  （已经转义，防注入；但"里面写了什么"由写的人决定）。如果这些文本本身敏感，导出文件要自己收好。
- **没做**：星图（S2）、分页、搜索、撤销撤回、按时间筛选。这一页只有最近 N 条。
- **没验**杀进程正好落在「页面已提交、erase 写到一半」那一瞬的表现——那由 `eraseExperience` 自己的
  事务/回滚负责，已有它的测试，这一层没有重复验。
