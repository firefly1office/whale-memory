# 先验语言节奏

当前优先级：**语言节奏 → 主动性 → 时间感 → 记忆精度**。这一批只验证日常闲聊的表达约束与 A/B 流程，不调整记忆参数、不接入线上角色、不更改存储。

## 两组有什么不同

同一个模型、同样的角色/上下文/状态、同样的 JSON 输出协议，两组都允许拒绝、不同意、不懂或不发送消息。

- baseline：普通角色聊天提示。它是离线参照，**不是线上鲸鲸的完整现状复刻**。
- rhythm：在普通提示后加入 90 个 Unicode 字符的上限（包含标点空白）、不列清单、不写结语式总结、允许短句/一个词、无需逐点回应、不强行共情与续聊。

这是一组组合约束，不能据此归因某一个提示词的单独效果。规则仅用于普通闲聊，不应套到操作说明、编程、精确信息交付或需要充分解释的场景。沉默也是角色选项，不按概率随机丢消息。不为“像人”编造不满、忙碌、共同经历或身体症状。

输出由 `inspect()` 做可检查的长度、常见列表和结语格式判定。超限不会截断、改写或择优重试；rhythm 组标记 blocked-style，保留原文用于比较。此门禁只覆盖列出的形式，不保证语义上没有讨好、总结或虚构感受，未来接入必须使用准入结果，不能直接发送 raw。本实验尚无发送消费者。

## 20 组虚构开发场景

包含多点闲聊、一个词、结束聊天、允许沉默、审美分歧、不懂的知识、拒绝剧透、拒绝虚假赞美、被敷衍、已声明的不愿聊，以及跨日话题与想说但没说的话。最后几题只向两组提供**相同的虚构状态**，不证明已经实现跨会话持续状态。

`chosenUnsaid` 是虚构的、角色已选中的待说材料。没有自动读取真实 unsaid。后续接入仍应由角色主动打开私聊抽屉、选择是否说；只有确认消息实际发出，才标为 spoken，失败或沉默保留原状态。记忆的递回继续遵守 `docs/injection.md` 的条件，不因相关就每轮注入。

## 复现和盲评

```sh
node --test tests/conversation-rhythm.test.mjs
node examples/conversation-rhythm/run.mjs
node examples/conversation-rhythm/run.mjs --provider <adapter.mjs> --out <新目录>
```

adapter 导出 `generate(messages,{signal})` 返回解析好的 JSON；可选导出 metadata 和 lastResponse（用量、完成原因等，不包含密钥）。采样共 40 次请求，可能产生费用。两组调用顺序随机选择起始组后交替，每题每组一次，无失败重试。默认只列计划，不调用模型。

输出：

- `report.json`：原始请求、哈希、输出、错误、用量和表面约束检查；不是人类评测分数。
- `blind.html`：发给评阅者的单文件离线页面。20 组顺序随机，A/B 位置随机且均衡，各组 10 次 baseline 在 A。无分组答案、无网络请求。失败题也保留，不悄悄排除。
- `key.json`：评测组织者保留的解盲映射，**不要与页面一起发给评阅者**。

只发送 `blind.html`，请评阅者独立填写并导出 JSON。问题分别是“哪份更像 AI”和“哪份更贴合场景”，都允许相近、无法判断；未填项不会强制当作某组胜出。页面保留原始回复（包括违反约束的输出），避免挑选合规样本抬高成绩。每人只纳入一份最终导出；reviewerId 只是导出标识，不认证身份，也不能识别同一个人多次导出。

```sh
node examples/conversation-rhythm/score.mjs <key.json> <review1.json> [review2.json]
```

结果中 aiLike 是“**更像 AI**”的票数，越多不是越好；fit 是“**更贴合场景**”的票数。平局、不确定、未填和生成错误都应保留报告。20 组开发题、单次生成、同一评阅者的多题相关性均限制结论，不能把投票比例称作意识、人格或普遍的类人准确率。

## 后续顺序

先收人类盲评，看短句和不总结是否真的改善观感，也检查是否损失内容、变得冷淡或机械。之后再做有来源的意见与拒绝、多轮后果、角色自主选择说出未竟话语和恰当递回记忆。真实对话须另行指定授权范围，仅保存在本地评测目录，不进入开源仓库。这里解决的是表达与行为表现，不测意识。
