# 一件事对我意味着什么

这是用于虚构经历的可选实验。借出仅有的一条独木舟，可能既实现了“我想让邻居去湖上”，也打乱了“我今天也想划船”。评估分别列出两个愿望，把各自的依据指回经历。遇到一把来历不明的钥匙，也可以暂时没有感想。

## 运行

仓库根目录执行 `node --test tests/emotion-bridge.test.mjs` 即可离线检查。宿主可以从同目录的 `appraisal.mjs` 导入 `reflectOnExperience`，传入一个虚构角色独占的临时库。

```js
const result = await reflectOnExperience({
  enabled: true,
  chatKey: 'local:owner',
  dir: fictionalStore,
  id: chosenExperienceId,
  generate: generateStructuredJson
})
```

默认关闭。宿主负责核实操作者、选择的经历、目录归属以及内容可发往哪个模型。`chatKey` 是受信宿主给出的上下文标识，不能用作身份验证。这个示例只处理指定的 `self / own-time` 经历；不得把共享数据库当成个人库。

`generate` 收到两条消息，返回解析好的 JSON 对象；也可以返回 `null` 或 `{skip:true}`。可用 `asOf` 查看当时已经写下的版本。模型能看到这件事的正文、场景、当时的念头和未完事项、已有感受，以及最近三条可见后记。模型返回前会再次检查本条经历的可见性和材料是否有变。传输中的内容一经交付给提供方就无法撤回。

成功时 `recordedFeelings` 单列原本写下的感受，`appraisal` 是本次生成的解释。每个愿望至少要引用事件和愿望各一处原文。推断原因、行动空间可以填未知；后来的理解需要后记支撑。直接引用能检出凭空编的出处，含义是否符合引文仍需判断。没有写下的愿望也可能真实存在，本接口只处理能指出来源的部分。

每个 `nowEffects` 判断都描述今天的愿望结果；有明确结果时必须逐字引用可见后记。`tradeoff` 中留下和放弃的愿望须与今天的判断一致。校验只保证字段自洽和引文有出处。方向说反也可能通过；模型也可以选 `none` 或 `unclear` 回避取舍。判断对错要另与预先标注比对。

关闭、跳过、不可读取各有独立状态。服务失败或证据格式错误会抛错，由宿主跳过本次回想。接口只返回结果，不落盘，不更新关系或心情，没有按轮调用的钩子。

## 虚构场景对照

`cases.json` 固定十个场景，包含两对相同事件与不同愿望、两件双重愿望、两件没有明确愿望的事、两条相关性不同的后记。每个场景用同一个模型各回答两次，一次只给结构和引文要求，另一次加上评估思路。比较时两组看到相同的经历。

如需重新采样，先在环境中配置有权使用的 `DEEPSEEK_API_KEY`，在仓库根目录执行以下命令。会向 DeepSeek 官方接口发起 20 次付费请求，文件名须尚未存在。操作使用临时虚构库；输出文件包含参数对应的场景指纹、回答、用量、结束原因和逐项判定。

```sh
node examples/emotion-bridge/probe.mjs comparison.json
```

一次完整试跑中，两组均在 4/4 个单愿望场景辨出愿望受助或受阻，在 2/2 个双愿望场景辨出两个方向，2/2 个无愿望场景留空，一条有关后记改变现在的理解，另一条无关后记未触发改判。行动空间一栏按预设答案，结构组 9/10，附加引导组 8/10。借出的船已经划走，能支持“眼下用不了船”；这道题将行动空间统一预设为未知，存在判分歧义。送书题则更清楚，仅凭“我把书送给妹妹”推断现在还有下一步可做，缺了依据。

这是一次单模型、每题每组一次的试跑。它展示了在记录中已经明写愿望时，模型可以做有据的解释。普通结构化提问已经做到大部分目标，附加引导的增益仍待验证；这组题也无法测量主观体验。
